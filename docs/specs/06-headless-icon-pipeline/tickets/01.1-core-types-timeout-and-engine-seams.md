### [NEW] [`packages/yume-engine/src/utils/timeout.ts`](file:///d:/Projects/YumeShelf/packages/yume-engine/src/utils/timeout.ts)
- Implement orthogonal promise timeout racing:
  ```typescript
  export interface WithTimeoutOptions<F = never> {
    timeoutMs?: number;
    signal?: AbortSignal;
    fallbackValue?: F;
    errorMessage?: string;
  }

  export async function withTimeout<T, F = never>(
    promise: Promise<T>,
    options: WithTimeoutOptions<F> = {}
  ): Promise<T | F> {
  ```
  - Parameterize `WithTimeoutOptions<F = never>` and return type `Promise<T | F>`. When `options.fallbackValue` is provided (e.g. `fallbackValue: null`), catch timeout expiration or signal abort and resolve `fallbackValue` instead of rejecting with `TimeoutError` or `signal.reason`.
  - Unconditionally attach an error suppression handler (`promise.catch(() => {})`) to the in-flight target `promise` at immediate function ingress *prior* to checking `signal?.aborted` or evaluating `fallbackValue`, guaranteeing that late asynchronous rejections (e.g. background filesystem I/O errors or cancelled streams) never escape as unhandled promise rejections in Node.js across any return path.
  - Only schedule a timeout timer if `typeof options.timeoutMs === 'number' && options.timeoutMs >= 0`. When `timeoutMs` is omitted or `undefined`, do not schedule any timer, allowing the promise to resolve normally or race strictly against `signal` if provided.
  - If `signal?.aborted` is true, immediately reject with `signal.reason` (or resolve `fallbackValue` if configured).
  - If `signal` is provided and active, attach `'abort'` listener (`signal.addEventListener('abort', onAbort)`) rejecting the race immediately upon abort (or resolving `fallbackValue` if configured).
  - In a `try...finally` block, guarantee that both `if (timerId) clearTimeout(timerId);` AND `if (signal && onAbort) signal.removeEventListener('abort', onAbort);` are executed to prevent event listener leaks.
