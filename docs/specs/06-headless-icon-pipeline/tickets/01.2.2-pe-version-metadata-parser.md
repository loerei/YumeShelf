# 01.2.2 — Postel's Law PE Version Metadata Parser ($S$)

## Epic
PRD: Move Headless Icon Extraction to @yumeshelf/engine

## What to build
Implement Postel's Law PE version metadata extraction by unifying with `packages/yume-engine/src/pe/version-parser.ts`. In `version-parser.ts`, elevate lenient UTF-16LE scanning (`extractStringFileInfoValue`) into `parseVsVersionInfo` as fallback when structural `VS_VERSIONINFO` parsing encounters malformed data. In `packages/yume-engine/src/pe/resource-decoder.ts`, implement `PeResourceDecoder.prototype.extractMetadata()` which traverses the resource tree to locate the leaf `RT_VERSION` (Type 16) entry via `this.getResourceDataEntry(RT_VERSION)`, extracts the `versionBuffer` slice from `this.rsrcSection.buffer`, and delegates payload parsing to `parseVsVersionInfo(versionBuffer)` rather than re-implementing bespoke `VS_VERSIONINFO` payload parsing (`extractStringFileInfoValue`). Map Windows metadata fields (`ProductName`, `FileDescription`, `CompanyName`, `FileVersion`, `ProductVersion`, `LegalCopyright`) to `PeVersionMetadata` properties. Implement distinct entrypoints `extractPeMetadata` (strictly synchronous) and `extractPeMetadataAsync` (asynchronous, accepting `options?: PeResourceDecoderOptions | IFileSystem`). Re-export `extractPeMetadata` and `extractPeMetadataAsync` from `packages/yume-engine/src/pe/index.ts`. Add unit tests in `packages/yume-engine/tests/pe-resource-decoder.test.ts` validating both standard and non-standard/corrupted version info payloads.
