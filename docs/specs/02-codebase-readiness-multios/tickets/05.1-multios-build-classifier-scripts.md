# 05.1 — MultiOS Build Output Classifier Scripts ($S$)

## Epic
PRD: Codebase Readiness for MultiOS Platform Support

## What to build
Update build artifact organizer and release scripts (`scripts/organize-build-output.js`, `scripts/release-artifacts.js`, and `scripts/write-release-checksum.js`) to categorize Darwin release artifacts (`.dmg`, `.dmg.blockmap`, `.zip`, `latest-mac.yml`) into symmetric `build_output/mac/` subdirectories (`application`, `feed`, `sha256`, `blockmap`, `unpacked/mac-unpacked`). In `scripts/organize-build-output.js`, guard top-level CLI execution with `if (require.main === module)`, parameterize `buildOutputDir` across functions, export `classifyEntry`, `normalizeNestedEntries`, `moveEntry`, and `organizeBuildOutput`, and ensure `classifyEntry` intercepts unpacked macOS directories (`'mac'`, `'mac-arm64'`, `'mac-universal'`) before checking `reservedNames`, routing them cleanly to `unpackedOutputDir` to prevent category name collisions with `build_output/mac/`. In `scripts/release-artifacts.js`, export the full canonical contract of modular macOS helpers (`getMacOutputDir`, `getMacApplicationOutputDir`, `getMacChecksumOutputDir`, `getMacFeedOutputDir`, `getMacBlockmapOutputDir`, `isMacArtifactName`, `isMacDmgArtifactName`, `isMacZipArtifactName`, `resolveMacArtifactPaths`). In `scripts/write-release-checksum.js`, import `getMacApplicationOutputDir` and `getMacChecksumOutputDir`, add `getMacApplicationOutputDir()` to `collectApplicationBinaries()`, route macOS artifacts to `getMacChecksumOutputDir()` in `resolveChecksumPath()`, and add a safety guard to `resolveNewestInstallerArtifactPath()` when only non-NSIS application binaries exist. In `package.json`, add standardized `"test:single": "node --test"` script under `"scripts"`. In `tests/release-artifacts.test.js`, mandate `t.afterEach` teardown hooks that recursively remove temporary fixture directories. Author test suite `tests/release-artifacts.test.js` validating categorization across Windows and macOS build artifacts.

## Explicit Assumptions & Boundaries
- Structural refactoring ($S$) adding multi-OS build artifact classification rules without triggering electron-builder compilation.
- Preserves existing Windows NSIS output categorization and naming conventions.
