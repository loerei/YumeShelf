# 01.2 — Renderer Custom Order Migration, Startup Seeding, and Lifecycle Bootstrap Wiring

## Epic
PRD 03: Virtual Nested Folders (App Folders) & Dual Workspace Views ("Favorite Desk" vs "Library")

## What to build

A renderer startup migration pipeline that migrates legacy custom ordering from `localStorage` (`yumeshelf_custom_order`) into `virtualTree` and `favoriteOrder` in `db.json`, reconciles against active library games via `normalizeCustomOrder`, enforces shared tree invariants, and wires into the application bootstrap lifecycle.

## Acceptance criteria

- [ ] In `src/renderer/lifecycle/bootstrap.ts`, guard migration to never execute when `games.length === 0` or library is unconfigured (`!bootstrapData?.config?.libraryPath`), and ensure `normalizeCustomOrder([])` is non-destructive by bypassing `writeCustomOrder([])`.
- [ ] Root `virtualTree`, `favoriteOrder`, and `schemaVersion: 2` are authoritatively initialized by the Main process migration runner $M_{1 \to 2}$ at storage boot. The renderer startup pipeline in `src/renderer/startup.ts:initApp` is scoped strictly to a one-time legacy custom order importer:
- [ ] If and only if `localStorage.getItem('yumeshelf_custom_order')` exists and valid library games are present (`games.length > 0`), read `yumeshelf_custom_order` from `storage` (`localStorage`, accepting an optional `storage?: Storage` parameter defaulting to `globalThis.localStorage` for headless test runners) and reconcile it against active library games via `normalizeCustomOrder`:
  - Discard stale keys for deleted games.
  - Resolve logical game aliases and identifiers to canonical physical `gameKey` references (`game.primaryInstance?.gameKey || game.gameKey`), filtering mapped entries through `seenCanonicalKeys = new Set<string>()` to eliminate duplicate physical keys resulting from canonical alias mapping.
  - Append any active library games missing from `localStorage` that satisfy `!seenCanonicalKeys.has(canonicalKey)` to `virtualTree.children` at root level.
  - Map the reconciled deduplicated sequence into `virtualTree.children` (`type: 'game'`) and extract favorited keys into `favoriteOrder`, ensuring strict `assertUniqueGameKeys` compliance before IPC dispatch.
- [ ] Enforce cold-start structural validation via `src/shared/virtual-tree/invariants.ts` (`03.1.1`): root node invariance (`id: 'root'`), duplicate node ID regeneration, cycle detection via visited ID set, and cumulative depth clamping ($\le 16$).
- [ ] Enforce atomic transactional gating: execute migration via atomic compound transaction by invoking `await electronAPI.migrateVirtualWorkspace({ tree, favoriteOrder })` strictly inside `src/renderer/startup.ts:initApp`, which persists reconciled `virtualTree` and `favoriteOrder` together inside `AtomicWriteCoordinator.mutate`. Upon successful resolution, remove legacy storage via `localStorage.removeItem('yumeshelf_custom_order')`. On fresh installs (where `yumeshelf_custom_order` is absent), zero IPC migration calls are dispatched, eliminating fresh install migration deadlock.
- [ ] In `src/renderer/lifecycle/bootstrap.ts:runRendererBootstrap`, delegate startup initialization solely to `await initApp(bootstrapData)`, removing redundant independent migration triggers to ensure a single authoritative execution path.
- [ ] In `src/renderer/startup.ts:initApp`, retrieve the latest virtual tree state via `electronAPI.getVirtualTree()` (or bootstrap payload). If legacy custom order exists in client storage (`localStorage.getItem('yumeshelf_custom_order')`) and library games are present (`games.length > 0`), execute one-time import via `await electronAPI.migrateVirtualWorkspace({ tree, favoriteOrder })` and remove `yumeshelf_custom_order` from `localStorage`.
- [ ] Sequentially update in-memory `virtualTree` and `favoriteOrder` in `UiRuntimeState` upon transaction completion.
- [ ] Add automated unit tests covering reconciled migration from `localStorage` using a `mockLocalStorage` test fixture / `storage` injection seam, non-destructive empty games guard, fresh install deadlock prevention, canonical key mapping, transactional persistence gating, alias resolution, stale key pruning, un-ordered game appending, cold-start cycle severing, depth clamping to 16 levels, root node invariance, and idempotent startup execution.
- [ ] Execute automated migration tests via `npm run test:vitest -- src/renderer/lifecycle/custom-order-migration.test.ts` with standard output containing `'✓ renderer/lifecycle/custom-order-migration.test.ts'` and `'Test Files  1 passed (1)'` with exit code 0.
