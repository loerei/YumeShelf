# 03.1.2 — Virtual Folder Tree Domain Reducer and Ancestry Resolver

## Epic
PRD 03: Virtual Nested Folders (App Folders) & Dual Workspace Views ("Favorite Desk" vs "Library")

## What to build
Implement pure tree mutation operations and ancestry resolution in `[NEW] src/shared/virtual-tree/manager.ts` (`VirtualTreeManager`), consuming types and invariants from `03.1.1`. Operations include folder creation, renaming, moving, reparenting, dissolving, empty folder pruning, and ancestry path resolution.

## Acceptance criteria
- [ ] Define `VirtualTreeManager` class skeleton and factory in `[NEW] src/shared/virtual-tree/manager.ts`, codifying its full public API: `createFolder`, `renameFolder`, `moveNode`, `dissolveFolder`, `pruneEmptyFolders`, `pruneMissingGames`, and `findAncestryPath`. Accept `TreeManagerOptions`:
  ```typescript
  export interface TreeManagerOptions {
    maxDepth?: number;          // default: 16
    maxNameLength?: number;     // default: 100
    idGenerator?: () => string; // default: () => crypto.randomUUID()
    now?: () => number;         // default: () => Date.now()
  }
  ```
- [ ] Implement `createFolder(tree, name, targetItemKeysOrIds, parentFolderId)` consuming injected `idGenerator` and `now` timestamps:
  - Validate `name` via `validateNodeName(name, options?.maxNameLength || 100)`, safely falling back to `'New Folder'` if invalid or whitespace-only.
  - Guard `parentFolderId` (defaulting to `'root'`): reject prototype keys (`__proto__`, `constructor`, `prototype`).
  - Index parent containers using prototype-less structures (`Map<string, VirtualFolderNode>` or `Object.create(null)`).
  - Deduplicate `targetItemKeysOrIds` and reject prototype keys.
  - Filter out or reject any target ID matching `'root'`, `tree.id`, or `parentFolderId`; return `{ folder: null as any, ok: false }` immediately if `targetItemKeysOrIds` contains `'root'` or `tree.id` to prevent reparenting the root container into a child folder.
  - Enforce depth bounds check: validate that `parentFolderId` resolves to an existing `VirtualFolderNode` whose depth satisfies `parentDepth < (options?.maxDepth || 16)`; if parent container is already at `maxDepth`, or if any target item is a folder whose subtree would cause cumulative depth to exceed `maxDepth`, return `{ folder: null as any, ok: false }` immediately.
  - In `renameFolder(tree, folderId, newName)`, enforce `validateNodeName` and `maxNameLength`; return `false` if `folderId === 'root'` or `folderId === tree.id`.
- [ ] Implement `moveNode(tree: VirtualFolderNode, sourceIdOrKey: string, targetFolderId: string, targetIndex?: number): boolean`:
  - Guard against root manipulation: return `false` if `sourceIdOrKey === 'root'` or `sourceIdOrKey === tree.id`. Explicitly permit `targetFolderId === 'root'`, allowing items to be moved or reparented back to the root library container.
  - Guard against missing or non-existent source nodes: search for `sourceIdOrKey` in tree containers; if the source item does not exist anywhere in the tree hierarchy, return `false` immediately without throwing `TypeError` or modifying the tree.
  - Guard against missing or invalid target containers: verify that `targetFolderId` exists in the tree hierarchy and that the resolved target node strictly satisfies `targetNode.type === 'folder'`; if `targetNode` does not exist or `targetNode.type !== 'folder'`, return `false` immediately without modifying or removing the source node.
  - Validate `targetIndex`, if provided, as a finite non-negative integer clamped to `[0, targetFolder.children.length]`.
  - Guard against self-target moves: return `false` immediately if `sourceIdOrKey === targetFolderId`.
  - Guard against descendant moves: if `sourceIdOrKey` is a folder node, query `findAncestryPath(tree, targetFolderId)`. If `findAncestryPath(tree, targetFolderId).some(item => item.id === sourceIdOrKey)` is `true`, return `false` immediately without modifying tree references (preventing isolated directed cycles).
  - Resolve whether source is a folder ID or game key.
  - Enforce cycle detection (`detectCycle`), target index adjustment, and cumulative depth clamping: validate that `targetFolderDepth + (isFolder ? getSubtreeDepth(sourceNode) : 1) <= (options?.maxDepth || 16)`; return `false` immediately if moving the item or subtree would exceed `maxDepth`.
  - Post-move cleanup (User Story 9): condition automatic empty folder dissolution strictly on inter-folder movement (`sourceContainingFolder.id !== targetFolderId` AND `sourceContainingFolder.id !== 'root'` AND `sourceContainingFolder.id !== tree.id`). If removing the node leaves its source containing folder empty, `sourceContainingFolder.id !== targetFolderId`, and `sourceContainingFolder.id !== 'root'`, automatically prune/dissolve the empty source folder up the tree hierarchy (stopping at root or a non-empty ancestor). If `sourceContainingFolder.id === targetFolderId` (intra-folder reordering), perform array repositioning (`splice`) and do NOT trigger empty folder pruning checks.
- [ ] Implement `dissolveFolder(tree, folderId)` mutation: return `false` immediately if `folderId === 'root'` or `folderId === tree.id`; reparent target children into parent node and remove folder container.
- [ ] Implement recursive post-order `pruneEmptyFolders(tree)` cleanup dissolving empty folders while preserving root.
- [ ] Implement `pruneMissingGames(tree: VirtualFolderNode, validGameKeys: Set<string>): { prunedKeys: string[] }` pruning missing game keys across all tree nesting depths.
- [ ] Implement ancestry resolution: `findAncestryPath(tree: VirtualFolderNode, targetNodeIdOrKey: string): AncestryItem[]` maintaining an internal `visited = new Set<string>()` and recursion depth bounds ($\le 16$, matching `options.maxDepth`), returning an ordered array of ancestor folder objects with `id` and `name` (immediately returning an empty array on duplicate folder ID or excessive depth to prevent stack overflow DoS).
- [ ] Automated unit tests covering all pure tree mutations, deterministic ID/time injection, root container mutation guards, cycle rejection, intra-folder reordering index adjustment, ancestry path finding, empty folder pruning, missing game pruning, and empty source folder dissolution on moveNode.
- [ ] Execute automated tree reducer unit tests via `npm run test:single -- tests/virtual-folder-tree.test.js` with standard output containing `'✔ VirtualTreeManager reducer'` and `'ℹ pass 15'` with exit code 0.
