# 01.4.2 — Folder Artwork Search & Desktop Entry Fallback ($S$)

## Epic
PRD: Move Headless Icon Extraction to @yumeshelf/engine

## What to build
Extract 36-pattern folder artwork search logic from `src/main/icon-pipeline/service.ts` into `@yumeshelf/engine` in `packages/yume-engine/src/icon/artwork-search.ts`. Define and export interface `LocalGameImageResult`, candidate patterns array `LOCAL_IMAGE_CANDIDATE_PATTERNS`, and extensions array `LOCAL_IMAGE_EXTENSIONS`. Implement `findLocalGameImage(targetPathOrDir, options)` checking `signal?.aborted` on each iteration of the candidate pattern search loop to enable early exit upon client request cancellation, tagging found candidates with `source: 'local-image'`. Implement pre-read candidate file size check `stat.size <= (options?.maxArtworkSize ?? options?.maxRsrcSize ?? DEFAULT_MAX_ARTWORK_SIZE)` before reading image buffers into memory, wrapping `fs.stat` in `try...catch` to cleanly skip missing files (`ENOENT`) and executing `continue` on oversized candidates. Integrate Active SVG Content Defense via `isSafeSvgBuffer` from `./svg-defense.js` when candidate images or resolved desktop entry icons point to `.svg` files. Fall back to Linux `.desktop` entry icons via `findDesktopEntryIcon` when no candidate image is matched, tagging matches with `source: 'desktop-entry'`. Implement synchronous variant `findLocalGameImageSync(targetPathOrDir)` and MIME-type helper `getImageMimeType(extOrPath: string)`. Re-export artwork search functions and types from `packages/yume-engine/src/icon/index.ts` and re-export `LocalGameImageResult` from `packages/yume-engine/src/types.ts`. Implement unit test suite in `packages/yume-engine/tests/artwork-search.test.ts` using `MockFileSystemProvider`.
