# 03.1 — Rust Playtime Helper Atomic Persistence Seam ($S$)

## Epic
PRD: Codebase Readiness for MultiOS Platform Support

## What to build
Extract shared `write_atomic(dest_path: &Path, content: &str) -> Result<()>` helper in `native/playtime-helper/src/main.rs` writing to `<dest_path>.tmp.<pid>.<timestamp_ms>_<counter>` (using a monotonic atomic counter with `AtomicU64::fetch_add(1, Ordering::Relaxed)`). Verify and create missing parent directories before opening with `create_new(true)`, capping collisions to a maximum of 10 retries on `ErrorKind::AlreadyExists` before returning a typed `std::io::Error`. Set restrictive mode `0o600` on Unix (`#[cfg(unix)]`), explicitly sync and drop handles prior to `fs::rename`, guarantee temporary file cleanup on all failure paths (including retry exhaustion), and provide test-configurable retry backoff with 0ms delay in tests and deterministic pseudo-hash jitter in production. Provide a test-injectable temporary path generator seam under `#[cfg(test)]` in `write_atomic_with_retry_config` (accepting a closure `FnMut(&Path, u32) -> PathBuf`) to enable deterministic collision testing for the 10-retry exhaustion limit and cleanup. Update `update_db_finalize` and `write_journal` to use `write_atomic`. In `native/playtime-helper/src/main.rs`, implement two-tiered error handling: if `parse_args()` returns `Err`, print the fatal error directly to `stderr` and exit immediately without referencing `config.log_path`; once `config` is parsed, persist any subsequent runtime errors to `config.log_path` via `append_log`.

## Explicit Assumptions & Boundaries
- Pure structural refactoring ($S$) hardening atomic file persistence and error handling across Windows and Unix platforms.
- Retains existing database serialization format and locking protocol.
