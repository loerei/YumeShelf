# 01.1.3 — Renderer UI Runtime State Scaffolding

## Epic
PRD 03: Virtual Nested Folders (App Folders) & Dual Workspace Views ("Favorite Desk" vs "Library")

## What to build
Extend the centralized reactive UI runtime state store (`UiRuntimeState`) in `src/renderer/state/ui-runtime-state.ts` and controller bindings in `src/renderer/bootstrap/app-composition.ts` with getters, setters, and subscriptions for `virtualTree`, `favoriteOrder`, `currentPath`, and `activeWorkspaceMode`.

## Acceptance criteria
- [ ] Extend `UiRuntimeState` typedef in `src/renderer/state/ui-runtime-state.ts` to declare `virtualTree: VirtualFolderNode | null`, `favoriteOrder: string[]`, `currentPath: string[]`, and `activeWorkspaceMode: 'favorites' | 'library'`. Guard any browser storage access via `typeof localStorage !== 'undefined' ? localStorage.getItem(...) : null` to preserve headless/Node testability.
- [ ] Implement getters and setters (`getVirtualTree`, `setVirtualTree`, `getFavoriteOrder`, `setFavoriteOrder`, `getCurrentPath`, `setCurrentPath`, `getActiveWorkspaceMode`, `setActiveWorkspaceMode`) on the `createUiRuntimeState()` instance.
- [ ] Pass state accessors into `startupControllerOptions` within `src/renderer/bootstrap/app-composition.ts`.
- [ ] Author automated unit tests in `src/renderer/state/ui-runtime-state.test.ts` verifying state mutation and accessor consistency, configuring an isolated in-memory `mockLocalStorage` fixture in `beforeEach` / `afterEach`.
- [ ] Execute automated unit tests via `npm run test:vitest -- src/renderer/state/ui-runtime-state.test.ts` with standard output containing `'✓ renderer/state/ui-runtime-state.test.ts'` and `'Test Files  1 passed (1)'` with exit code 0.
