# 04.1 — App Updater Strategy Interface Seam & NsisUpdaterStrategyAdapter ($S$)

## Epic
PRD: Codebase Readiness for MultiOS Platform Support

## What to build
Extract `AppUpdaterStrategy`, `AppUpdateCheckResult`, `AppUpdaterActionResult`, and `AppUpdaterStrategyOptions` in `src/main/app-updates/updater-strategy.ts`. Implement `NsisUpdaterStrategyAdapter` wrapping `NsisUpdaterService` and implement `NoopUpdaterStrategy` as a safe fallback on unsupported platforms, requiring both to implement explicit `dispose(): void`. In `src/main/app-updates.ts`, extend `AppUpdateServicesOptions` with `updaterStrategy?: AppUpdaterStrategy`, `updaterOptions?: AppUpdaterStrategyOptions`, and `platform?: NodeJS.Platform`, consuming `options.updaterStrategy || createAppUpdaterStrategy(options.updaterOptions, options.platform)`. Wrap optional deferred installation methods in `createAppUpdateServices` (`prepareDeferredInstallOnLaunch`, `beginDeferredInstallOnLaunch`, `runDeferredInstallOnLaunch`) with safe default fallbacks to guard against strategies that do not support deferred installation, and expose `dispose(): void` delegating to `updater.dispose?.()`. In `check-service.ts`, `download-install.ts`, and `helpers.ts`, update context to consume `context.updaterStrategy || context.nsisUpdaterService || new NoopUpdaterStrategy()`. Extend existing `tests/app-updates-background.test.js` appending new test cases for `NoopUpdaterStrategy` and `NsisUpdaterStrategyAdapter`, preserving all 11 existing passing test suites.

## Explicit Assumptions & Boundaries
- Pure structural refactoring ($S$) introducing polymorphic updater strategy interfaces without altering production Windows NSIS updater behavior.
- Maintains 100% backward compatibility for existing callers and test fixtures injecting `nsisUpdaterService`.
