## Epic

## What to build
Implement empty folder placeholder prompt and manual executable addition in `src/renderer/library-grid.ts`:
1. Empty Folder Placeholder Rendering:
   - When a folder section contains zero games (`section.isEmpty === true` or `section.games.length === 0`):
       - Unfiltered Empty State: If no category filter is active (`!activeCategoryId`) and the folder section contains zero games in the unfiltered library state (`allGames`), render the empty state placeholder button inside the section grid:
        ```html
        <div class="empty-folder-prompt"><button type="button" class="manual-add-btn"></button></div>
        ```
        The button text must be set via `textContent = t('manual_add_prompt', ...)` and its accessible name assigned via `btn.setAttribute('aria-label', `${t('manual_add_prompt', 'Your Game Is Not Scanned? Manually Add Them Here.')} — ${section.displayName}`)` (or sanitized via `escapeHtml(section.displayName)`), strictly prohibiting raw unescaped template interpolation of folder names or aliases into HTML strings to prevent attribute escape and DOM XSS vulnerabilities. The button must declare explicit `type="button"` and a contextual accessible name complying with WCAG 2.5.3 (Label in Name) by ensuring the accessible name starts with or contains the visible button label text, preventing speech-input activation failure while disambiguating the folder section context. The `.empty-folder-prompt` container must span all columns (`grid-column: 1 / -1;`) in the CSS grid to prevent squishing into a single card column, providing a centered layout box with minimum height reservation (`min-height: 120px;`) and dashed accent border.
      - Filtered View Invariant: When a category filter is active (`activeCategoryId` is truthy) and a folder section contains zero matching games (`section.games.length === 0`), do NOT render `.empty-folder-prompt` ("Your Game Is Not Scanned? Manually Add Them Here."); instead, deterministically render a neutral filtered empty message container (`<div class="filtered-folder-empty-state">${t('no_matching_games_in_folder', 'No matching games in this folder')}</div>`), ensuring users are informed that games in this folder do not match the active filter while preventing blank screens on individual folder tabs (`activeTabId !== 'all' && activeTabId !== 'fav'`).
    - Library Grid Empty State Bypass: In `renderLibraryGrid`, when `visibleGames.length === 0`, if `sortType === 'folder'`, `!activeCategoryId`, and configured library roots exist (`rootPaths.length > 0`), do NOT invoke `renderLibraryEmptyState(d)` and do NOT return early. Instead, proceed to section projection via `projectLibrarySections` so that empty folder sections (`isEmpty: true`) are rendered into `refs.gameGridWrapper`, exposing the `.empty-folder-prompt` button for each configured folder. Global `renderLibraryEmptyState(d)` in folder mode is rendered only when zero library root directories are configured (`rootPaths.length === 0`).
 2. Manual Game Dialog & Ingestion:
    - Maintain an `isSelecting: boolean = false` in-flight guard: if `isSelecting` is true or if section reordering is in progress (`options.isReordering?.() || isReordering`), immediately return to prevent duplicate concurrent native OS file picker dialogs or race conditions with active section FLIP animations and IPC persistence transactions.
    - Click listener on `.manual-add-btn`:
      - If `options.isReordering?.() || isReordering || isSelecting` is true, immediately return.
      - Sets `isSelecting = true`.
      - Immediately applies `aria-disabled="true"`, `aria-busy="true"`, and interaction blocking to `.manual-add-btn` to prevent duplicate clicks while the OS dialog initializes.
      - In-flight progress feedback: throughout the asynchronous `options.electronAPI.addManualGame({ folderPath: section.path })` invocation, `.manual-add-btn` displays an active in-flight status label (localized via `options.i18n?.('empty_folder_selecting') ?? 'Selecting...'`) and dynamically updates its accessible name via `btn.setAttribute('aria-label', ...)` to contain the visible in-flight status text alongside folder context (e.g. `${t('empty_folder_selecting', 'Selecting...')} — ${section.displayName}`), satisfying WCAG 2.5.3 throughout all interaction states while ensuring DOM XSS immunity.
      - In a `try ... catch ... finally` block, invokes `options.electronAPI.addManualGame({ folderPath: section.path })`, providing `section.path` as the target enclosing folder so that any executable selected within or beneath that folder (including in wrapper subdirectories) is assigned to that folder section per Objective User Criteria #7:
        - If response is canceled (`result?.canceled === true`), cleanly resets the button state to the default prompt, and takes no further action.
       - If response is successful (`result?.ok === true && result.game`), forwards `result.game` to injected `options.onGameAdded?.(result.game)`.
       - `options.onGameAdded` updates in-memory game state (`state.setAllGames(...)`), re-annotates games, and re-renders the library grid, immediately displaying the newly added game inside that folder section while explicitly anchoring and restoring keyboard focus to the newly rendered game card element (via `data-game-key`) or the section container, preventing focus eviction to `document.body`.
        - If response returns an error or rejects, displays an actionable localized notification via `const errorCode = result?.error; const localizedMsg = errorCode ? (options.i18n?.(`error_${errorCode.replace(/-/g, '_')}`) ?? (typeof window !== 'undefined' ? (window as any).i18n?.t?.(`error_${errorCode.replace(/-/g, '_')}`) : undefined)) : null; options.showToastPill?.(localizedMsg || (options.i18n?.('toast_manual_add_failed') || 'Failed to add game manually'))` and logs structured diagnostic context (`console.error('[LIBRARY_GRID][MANUAL_ADD] Failed to manually add game to folder:', { folderPath: section.path, error: result?.error || err })`) without crashing the renderer or corrupting grid state. Localization in `handleManualAddGame` must rely strictly on the injected `options.i18n` dependency injection seam with safe fallback strings; direct ambient global access to `(window as any).i18n` is prohibited unless guarded by `typeof window !== 'undefined'`, enabling unit tests to verify error recovery toasts deterministically by passing a mock `i18n` without requiring global `window` stubbing.
      - In `finally`, removes `aria-busy="true"` and `aria-disabled="true"`, restores button text and idle accessible name (`aria-label`), and resets `isSelecting = false`.

  ```typescript
  onGameAdded: (game) => {
    const platform = (state as any).targetPlatform || (typeof process !== 'undefined' ? process.platform : 'win32');
    const getGameFolder = (item: any) => item?.folderPath || item?.primaryInstance?.folderPath || item?.primaryGame?.folderPath || '';
    const getGameKeys = (item: any) => [item?.gameKey, item?.representativeKey, item?.gameId, ...(item?.instances?.map((i: any) => i.gameKey) || [])].filter(Boolean);
    const addedKeys = new Set(getGameKeys(game));
    const targetFolder = getGameFolder(game) ? normalizePathForPlatform(getGameFolder(game), platform) : '';

    state.setAllGames([
      ...state.getAllGames().filter((g: any) => {
        if (g.gameId && game.gameId && g.gameId === game.gameId) return false;
        const existingKeys = getGameKeys(g);
        if (existingKeys.some(k => addedKeys.has(k))) return false;
        const existingFolder = getGameFolder(g) ? normalizePathForPlatform(getGameFolder(g), platform) : '';
        if (targetFolder && existingFolder && existingFolder === targetFolder) return false;
        return true;
      }),
      game
    ]);
    libraryRuntime.reannotateGames?.();
    libraryRuntime.sortGames(state.getCurrentSort());
  },
  ```
