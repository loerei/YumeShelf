## Epic

## What to build
Harden network protocol security, ingress path validation, client request cancellation, and response headers in `src/main/icon-pipeline/service.ts`. In `handleProtocolRequest`:
1. Validate `targetPath`: reject remote UNC network paths (`/^[\\\/]{2}/`), Windows NT device namespace paths (`\??\UNC\...` / paths containing `'?'` or starting with `/^[\\\/]\?/`), Windows DOS device names (`/^(con|prn|aux|nul|com[1-9]|lpt[1-9])([.:\s].*)?$/i`), colons beyond drive letter index 1 (`targetPath.slice(2).includes(':')`), and null bytes (`\0`, `%00`), returning HTTP 400 Bad Request. In `resolveIconDataUrl`: return `null` for invalid paths.
2. Use cross-platform path validation: `path.isAbsolute(targetPath) || path.posix.isAbsolute(targetPath) || path.win32.isAbsolute(targetPath)` (ensuring Windows drive paths evaluate as absolute on Linux/macOS runners and POSIX paths evaluate on Windows in-memory test environments), normalize slashes with `.replace(/\\/g, '/')`, and inspect all segments for DOS devices.
3. Immediate client abort guard: if `request.signal?.aborted` before performing disk I/O, immediately return `new Response(null, { status: 499, headers: defensiveHeaders })`. If extraction yields null and `request.signal?.aborted` is true, terminate cascade with HTTP 499 carrying defensive security headers instead of falling through to slower worker pool or shell fallbacks.
4. Uniform defensive headers: attach `'X-Content-Type-Options': 'nosniff'` and `'Content-Security-Policy': "default-src 'none'; style-src 'unsafe-inline'"` across all protocol responses (200 cache hits, local artwork, PE extraction, shell fallbacks, 400 bad request, 404 not found, 499 client abort, and 500 server error).
5. Add comprehensive unit and integration tests in `tests/icon-pipeline-optimization.test.js` asserting UNC path rejection, DOS device and ADS rejection, null byte rejection, HTTP 499 cancellation with headers, and presence of defensive security headers.

### [MODIFY] [`src/main/icon-pipeline/service.ts`](file:///d:/Projects/YumeShelf/src/main/icon-pipeline/service.ts)
- Path validation helper `isValidIconTargetPath(targetPath: string): boolean`:
  ```typescript
  export function isValidIconTargetPath(targetPath: string): boolean {
    if (!targetPath || typeof targetPath !== 'string') return false;
    // Reject null bytes and URL-encoded null bytes
    if (targetPath.includes('\0') || targetPath.includes('%00')) return false;
    // Reject remote UNC paths (\\server\share or //server/share or multiple slashes)
    if (/^[\\\/]{2}/.test(targetPath)) return false;
    // Reject Windows NT device namespace prefixes (\??\UNC\... or /?/UNC/...) and question mark characters
    if (targetPath.includes('?') || /^[\\\/]\?/.test(targetPath)) return false;
    // Disallow colons beyond drive letter designation at index 1 (blocks NTFS ADS and DOS device suffixes)
    if (targetPath.slice(2).includes(':')) return false;
    // Cross-platform absolute path verification
    const isAbsolute = path.isAbsolute(targetPath) || path.posix.isAbsolute(targetPath) || path.win32.isAbsolute(targetPath);
    if (!isAbsolute) return false;

    // Reject Windows DOS device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9) across all path segments
    const normalized = targetPath.replace(/\\/g, '/');
    const segments = normalized.split('/').filter(Boolean);
    const dosDeviceRegex = /^(con|prn|aux|nul|com[1-9]|lpt[1-9]|conin\$|conout\$)([.:\s].*)?$/i;
    if (segments.some(seg => dosDeviceRegex.test(seg))) return false;

    return true;
  }
  ```
