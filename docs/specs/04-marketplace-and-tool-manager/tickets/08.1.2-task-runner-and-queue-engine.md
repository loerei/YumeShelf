# 08.1.2 — Task Runner & Queue Execution Engine

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The `TaskRunnerService` under `src/main/addons/task-runner.service.ts` managing asynchronous on-demand batch tasks (`strategy: 'task'`), 1-active FIFO queue scheduling, cross-subsystem mutual exclusion against `PlaytimeSessionManager`, safe non-shell child process execution, test seams (`spawnFn`, `gracePeriodMs`, `throttleMs`), cancellation signaling with escalation, shutdown lifecycle hooks (`dispose()`), rate-limited IPC broadcasting via `addon:task-status`, pull-based `addon:get-task-state`, and IPC preload exposure on `window.electronAPI`.

## Explicit Assumptions & Boundaries
- Concurrency limit: Exactly 1 active task process at a time. New task requests are appended to a FIFO queue.
- Mutual exclusion: `TaskRunnerService` verifies `!playtimeSessionManager.isGameActive(gameKey)` before starting a task on `gameKey`, rejecting with typed `GameRunningConflictError`.
- Child process execution strictly uses `child_process.spawn(executable, argsArray, { shell: false })` to prevent shell argument injection.
- Application exit terminates active child processes cleanly via `app.on('before-quit')`.
- All decrypted credentials in CLI arguments, error messages, and broadcast events are sanitized via `08.1.1` redaction before logging or IPC transmission.

## Acceptance criteria
- [ ] Implement `TaskRunnerService` under `src/main/addons/task-runner.service.ts`, supporting optional `paths?: { addonsDir?: string }`, `spawnFn?: typeof child_process.spawn`, `killTreeFn?: (pid: number) => Promise<void>`, `isGameActive?: (gameKey: string) => boolean`, `webContentsProvider?: () => Electron.WebContents[]`, `broadcastFn?: (channel: string, payload: any) => void`, `gracePeriodMs?: number` (defaulting to 3,000ms), and `throttleMs?: number` (defaulting to 50–100ms) in constructor for deterministic testability.
- [ ] Manage in-memory FIFO queue `taskQueue: Array<QueuedTask>`.
- [ ] Enforce mutual exclusion: before starting a task on `gameKey`, verify `!playtimeSessionManager.isGameActive(gameKey)`. If game is running, reject or hold task with typed `GameRunningConflictError`.
- [ ] Execute 1 active task at a time, automatically advancing to the next queued item upon completion or failure.
- [ ] Implement `dispose(): Promise<void>` / `shutdown()` lifecycle handler hooked to Electron's `app.on('before-quit')` (and `SIGINT`/`SIGTERM`), terminating any active child process and process tree with `gracePeriodMs` signal escalation and immediately clearing any pending broadcast throttle timers (`if (this.broadcastTimer) { clearTimeout(this.broadcastTimer); this.broadcastTimer = null; }`).
- [ ] Spawn child processes safely:
  - Resolve absolute executable path strictly within `userData/addons/<id>/` based on relative `manifest.entryPoint`. Prohibit raw `.bat` or `.cmd` script entry points without an explicit runtime interpreter (CVE-2024-27980).
  - Execute using `child_process.spawn(entryPoint, argsArray, { cwd, shell: false, env: { ...process.env, ...taskEnv } })`. Passes sensitive credentials decrypted from the vault exclusively through `taskEnv`, preventing command-line argument snooping via OS process tables.
  - Integrate `08.1.1` parser to consume stdout streams.
- [ ] Implement IPC handlers & Renderer broadcaster:
  - IPC `addon:run-task`: Enqueue task and return `{ queued: boolean, active: boolean, taskId: string }`.
  - IPC `addon:get-task-state`: Return `{ activeTask: AddonTaskStatusEvent | null, queuedTasks: AddonTaskStatusEvent[] }` for reactive UI state hydration.
  - IPC `addon:cancel-task`: Send `SIGTERM` (escalating to `SIGKILL` after `gracePeriodMs`) to running task PID, or remove from queue if pending.
  - Event `addon:task-status`: Broadcast `AddonTaskStatusEvent` containing `taskId`, `addonId`, `gameKey`, `phase: 'queued' | 'running' | 'completed' | 'cancelled' | 'error'`, `percent`, `step`, `message`, and `error` to WebContents, rate-limited via `throttleMs` throttling and checking `!win.isDestroyed()` before transmission.
  - Sanitize all logged CLI arguments and IPC event payloads using `08.1.1` credential redaction.
- [ ] Expose task queue IPC channels (`addon:run-task`, `addon:get-task-state`, `addon:cancel-task`, `addon:task-status`) on `window.electronAPI` in `src/preload.ts` and declare typed signatures in `src/shared/types/ipc.d.ts`.
- [ ] Unit & integration tests in `tests/task-runner.test.js` verifying FIFO task queueing order (1 active task at a time), game running conflict rejection via injected `isGameActive` predicate, synthetic child process fixtures with `PassThrough` duplex streams (`stdout`, `stderr`, `stdin`) and `setImmediate` event emission for deterministic event streaming/cancellation escalation, application exit teardown, credential redaction in logs/events, and IPC state query / broadcasting. Implement `afterEach` / `after` asynchronous teardown hook calling `service.dispose()`.
- [ ] Execute automated tests via `npm run test:node -- tests/task-runner.test.js`.
