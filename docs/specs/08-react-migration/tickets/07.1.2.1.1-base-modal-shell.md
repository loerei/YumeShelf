## What to build
Implement the foundational, reusable compound `<Modal>` dialog container shell portaled into `#portal-root` (with headless `document.body` fallback), establishing focus trapping, backdrop click dismissal, and Escape key integration with `OverlayProvider`:

1. **Portal Root Container (`src/index.html`)**:
   - Verify [`src/index.html`](file:///d:/Projects/YumeShelf/src/index.html) provides `<div id="portal-root"></div>` alongside `<div id="react-root"></div>` (established in Ticket 03.2).

2. **Compound Modal Shell Component (`src/renderer/components/modals/Modal.tsx`)**:
   - Create [`src/renderer/components/modals/Modal.tsx`](file:///d:/Projects/YumeShelf/src/renderer/components/modals/Modal.tsx):
     - Reusable compound modal dialog container accepting `isOpen: boolean`, `onClose: () => void`, `title?: string`, `id?: string`, `className?: string`, `panelClassName?: string`, and `children: React.ReactNode`:
       ```typescript
       export interface ModalProps {
         isOpen: boolean;
         onClose: () => void;
         title?: string;
         id?: string;
         className?: string;
         panelClassName?: string;
         children: React.ReactNode;
       }
       ```
       Combines root overlay class via `['modal-backdrop', className].filter(Boolean).join(' ')` and dialog panel class via `['modal-panel', panelClassName].filter(Boolean).join(' ')` without third-party classname utility dependencies.
     - Exports compound subcomponents `<Modal.Header>`, `<Modal.Body>`, and `<Modal.Footer>`. Generates a unique title element ID via `useId()` (`const generatedId = useId(); const titleId = id ? `${id}-title` : `modal-title-${generatedId}`;`) provided through `ModalContext`, and links the dialog root to the title element via `aria-labelledby={titleId}` (with fallback `aria-label={title ?? undefined}`) provided through `ModalContext` so composing `<Modal.Header>` without repeating `title` on `<Modal>` retains accessible labelling under WCAG 4.1.2. `ModalHeaderProps` is formally typed (`title?: string; children?: React.ReactNode; id?: string; className?: string; onClose?: () => void;`), rendering dialog title content with `<h2 id={id ?? titleId} className="modal-title">{children ?? title}</h2>` supporting both string title prop and compound slot composition, and an explicit, accessible close button equipped with an inline vector SVG icon bound to `currentColor` (strictly rejecting raw Unicode characters like "×") and an explicit accessible name and native tooltip (`aria-label="Close dialog"`, `title="Close dialog"`), calling `(onClose ?? contextClose)()` on click or `Enter`/`Space` keyboard activation.
     - Resolves the portal target container with defensive fallback to `document.body` so headless and isolated component tests run without container mounting errors when `#portal-root` is absent from jsdom:
       ```typescript
       const portalTarget = document.getElementById('portal-root') ?? document.body;
       return createPortal(modalContent, portalTarget);
       ```
     - Exclusively owns the local dialog DOM focus lifecycle and accessibility landmarks:
       - Root dialog container element declares `tabIndex={-1}`, `role="dialog"`, `aria-modal="true"`, and `aria-labelledby={titleId}`.
       - Upon opening (`isOpen === true`), captures `document.activeElement` into a trigger ref anchor and programmatically moves initial focus into the dialog container (`dialogRef.current?.focus()`).
       - While open, traps focus by cycling Tab / Shift+Tab within its internal `dialogRef` container.
       - Accepts optional `fallbackFocusRef?: React.RefObject<HTMLElement | null>` on `ModalProps`. Focus restoration is tracked via `wasOpenRef = useRef(false)` and executed strictly during `isOpen === true` effect cleanup to prevent cold-boot focus theft and double restoration. Before restoring focus, guards against hijacking if active focus already transitioned to a surviving element outside the dialog (`active instanceof HTMLElement && active.isConnected && active !== document.body && active !== document.documentElement && (!dialogRef.current || !dialogRef.current.contains(active))`). If `triggerRef.current && triggerRef.current.isConnected`, restores focus to trigger; otherwise, if `fallbackFocusRef.current && fallbackFocusRef.current.isConnected`, restores focus to fallback target, completely eliminating focus eviction to `document.body`.
       - Manages backdrop click dismissal verifying that pointer-down and click events both originate directly on the backdrop container (`e.target === backdropRef.current`), preventing inadvertent modal dismissal when a user selects text within a modal form field and releases the pointer outside the dialog panel.
       - For local Escape handling, dispatches on the root dialog element via `onKeyDown={(e) => { if (e.defaultPrevented) return; if (e.key === 'Escape') { e.preventDefault(); onClose(); } }}` when focused. If an internal child interactive control consumes Escape via `e.preventDefault()`, `<Modal>` leaves the dialog open. When `<Modal>` handles Escape and executes `onClose()`, it calls `e.preventDefault()` to cancel bubbling and prevent duplicate invocation at `OverlayProvider`'s global `window` listener. Prohibits `<Modal>` from attaching unencapsulated global `window` or `document` listeners.
       - Enforces layout stability via `scrollbar-gutter: stable` declared on `html, body` in `src/styles/base.css` (Ticket 01), continuously reserving scrollbar space to eliminate Cumulative Layout Shift (CLS) on modal open and close transitions.
       - Enforces local stacking context containment via `isolation: isolate` on `<Modal />` dialog shells and `#portal-root` containers, binding overlay elevation directly to tokenized design system scales declared in `src/styles/theme.css` (`--zIndex-modal: 2000`) rather than arbitrary untokenized integers.
       - Declares explicit media rules for users requesting reduced motion (`prefers-reduced-motion: reduce`), transitioning modal backdrop opacity and dialog scaling with immediate 0ms duration to eliminate animation drift.

## Acceptance Criteria
- [ ] `src/index.html` provides `<div id="portal-root"></div>` alongside `<div id="react-root"></div>` (established in Ticket 03.2).
- [ ] Compound `<Modal>` component implemented in `src/renderer/components/modals/Modal.tsx` exposing subcomponents `<Modal.Header>`, `<Modal.Body>`, and `<Modal.Footer>`. `<Modal.Header>` renders an accessible close button with `aria-label="Close dialog"`, `title="Close dialog"`, and an inline vector SVG icon bound to `currentColor` (strictly rejecting raw Unicode characters like "×"), invoking `onClose()` on click or `Enter`/`Space` activation.
- [ ] `ModalProps` exports `isOpen: boolean; onClose: () => void; title?: string; id?: string; className?: string; panelClassName?: string; fallbackFocusRef?: React.RefObject<HTMLElement | null>; children: React.ReactNode;`, merging `className` onto the backdrop overlay container (`['modal-backdrop', className].filter(Boolean).join(' ')`) and `panelClassName` onto the inner dialog panel (`['modal-panel', panelClassName].filter(Boolean).join(' ')`) without external utility dependencies.
- [ ] Modal portals its DOM subtree into `document.getElementById('portal-root')` with fallback to `document.body`.
- [ ] Modal root element sets accessible dialog attributes: `role="dialog"`, `aria-modal="true"`, `tabIndex={-1}`, and `aria-labelledby` referencing the title element inside `<Modal.Header>` (or `aria-label={title}`), providing a valid accessible name to screen readers under WCAG 4.1.2.
- [ ] Modal implements internal focus trapping cycling between first and last focusable elements on `Tab` and `Shift+Tab`.
- [ ] Modal restores focus to trigger element upon closing, guarded by `triggerRef.current.isConnected` check, falling back to `fallbackFocusRef.current` when trigger is disconnected.
- [ ] **Given** `<Modal isOpen={false} />` renders on cold boot, **when** mounted, **then** `restoreFocus()` does not execute and does not steal focus from existing document elements.
- [ ] **Given** a modal unmounts while `isOpen` is true (conditional unmount) or closes when its captured invoking trigger element is disconnected from the DOM, **when** focus restoration executes, **then** focus transfers deterministically to `fallbackFocusRef.current` with zero focus eviction to `document.body`.
- [ ] **Given** `<Modal />` unmounts conditionally or closes, **when** `document.activeElement` is detached (`active.isConnected === false`) or evicted to `document.documentElement` / `document.body`, **then** `restoreFocus()` does not treat the detached element as an active external control and deterministically transitions focus to `fallbackFocusRef.current`.
- [ ] **Given** focus has already transferred to a surviving list item or external container outside `dialogRef`, **when** the modal unmounts, **then** `restoreFocus()` does not hijack focus away from the newly focused element.
- [ ] Modal dismisses on backdrop overlay click, verifying that both pointer-down and click events originate directly on the backdrop container (`e.target === backdropRef.current`), preventing inadvertent dismissal during internal text selection.
- [ ] Modal handles Escape key on local dialog container (validating `if (event.defaultPrevented) return;`, calling `event.preventDefault()`, and invoking `onClose()`) without registering global window event listeners.
- [ ] Modal container and application root layout enforce scrollbar layout stability (`scrollbar-gutter: stable`), continuously reserving scrollbar space and preventing Cumulative Layout Shift (CLS) during modal open and close transitions.
- [ ] Modal shell and portal root container enforce local stacking context containment (`isolation: isolate`) and bind dialog elevation directly to design system tokens declared in `src/styles/theme.css` (`--zIndex-modal`), preventing bleed-through from background elements and unmanaged z-indices.
- [ ] `src/styles/modals.css` created and imported into `src/style.css`, providing complete visual styling for `<Modal>`, `<Modal.Header>`, `<Modal.Body>`, `<Modal.Footer>`, `.duplicate-stack-dialog`, `.duplicate-stack-instances` (enforcing `scrollbar-gutter: stable;` against instance deletion layout shift), and `.modal-header h2 .duplicate-stack-count` (with `font-size: 13px; font-weight: normal; color: var(--text-sub, #b3b3b3);`), with zero-duration transitions under `prefers-reduced-motion: reduce`.
- [ ] `src/styles/modals.css` defines tokenized `.danger-btn` styling bound to `var(--danger-btn-bg, #e03131)` and hover `var(--danger-btn-hover-bg, #c92a2a)` with accessible hover, focus, and `aria-disabled="true"` states for destructive modal confirmation actions.
- [ ] `src/styles/modals.css` declares `.modal-panel` with `max-height: calc(100vh - 48px); display: flex; flex-direction: column;` and `.modal-body` with `flex: 1 1 auto; min-height: 0; overflow-y: auto; scrollbar-gutter: stable;` to guarantee modal footers remain pinned within the desktop viewport regardless of content length.
- [ ] **Given** a compound `<Modal>` rendered with `<Modal.Header>`, `<Modal.Body>`, and `<Modal.Footer>`, **when** inspected in the DOM, **then** the elements map to structural classes `.modal-panel`, `.modal-header`, `.modal-body`, and `.modal-footer`, binding to `src/styles/modals.css` flex-column and `overflow-y: auto` scroll containment rules.
- [ ] Vitest unit tests in `Modal.test.tsx` pass cleanly under Vitest, including assertions verifying that activating the `<Modal.Header>` close button via click or keyboard activation invokes `onClose()`.
- [ ] `npm run typecheck` passes with zero errors.
