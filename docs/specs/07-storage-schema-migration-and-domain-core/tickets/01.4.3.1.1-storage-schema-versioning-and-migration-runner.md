## What to build
Establish explicit database schema versioning and a minimal isolated storage migration runner executed at storage boot per Kent Beck $S \to B$ preparatory refactoring and `DATA-SCHEMA-VERSIONING.md`, ensuring all domain loaders, repositories, and UI view models consume strictly canonical `schemaVersion: 1` data without heuristic property sniffing or transient migration flags.

### 1. Schema Version Register & Sequential Migration Runner (`src/main/library-state/migrations.ts`)
- Explicit Version Register:
  - Declare `export const CURRENT_SCHEMA_VERSION = 1;`.
  - Extend root database envelope `LibraryDatabase` and declare `StoredGameRecord`:
    ```typescript
    export interface StoredGameRecord {
      folderPath: string;
      exePath: string;
      name?: string;
      customName?: boolean;
      folderName?: string;
      gameKey?: string;
      relativePath?: string;
      favorite?: boolean;
      playtime?: number;
      lastPlayed?: number;
      runInBackground?: boolean;
      autoTranslate?: boolean;
      dateAdded?: number;
      engine?: string | null;
      saveFolderOverride?: string;
      manual?: boolean;
      platform?: 'macos' | 'windows' | 'linux';
      sizeBytes?: number;
      sizeMtime?: number;
      [key: string]: any;
    }

    export interface LibraryDatabase {
      schemaVersion: number;
      config: LibraryConfig;
      games: Record<string, StoredGameRecord>;
      titleResolutionConfig?: {
        titleDisplayMode?: string;
        displayProductCodes?: boolean;
        preferredLocale?: string;
      };
      [key: string]: any;
    }
    ```
  - For unversioned legacy stores (missing `schemaVersion`), default `schemaVersion` to `0`.
- Sequential Migration Runner:
  - Export `runStorageMigrations(db: any, context: LibraryContext, targetPlatform?: PlatformInput, targetVersion: number = CURRENT_SCHEMA_VERSION): Promise<LibraryDatabase>`.
  - Migrations execute linearly ($M_{0 \to 1} \to \dots$) through an isolated runner loop wrapped with structured diagnostics:
    ```typescript
    let currentVersion = db.schemaVersion ?? 0;
    console.info('[STORAGE_MIGRATIONS] Starting storage migrations:', {
      initialVersion: currentVersion,
      targetVersion
    });
    while (currentVersion < targetVersion) {
      const nextVersion = currentVersion + 1;
      const migrationFn = MIGRATIONS[nextVersion];
      if (!migrationFn || typeof migrationFn !== 'function') {
        console.error('[STORAGE_MIGRATIONS] Missing migration function for schema version:', {
          currentVersion,
          nextVersion,
          targetVersion
        });
        throw new Error(`Missing migration step for schema version ${nextVersion}`);
      }
      try {
        const migratedDb = await migrationFn(db, context, targetPlatform);
        if (!isPlainObject(migratedDb)) {
          console.error('[STORAGE_MIGRATIONS] Migration step returned invalid non-plain object database structure:', { currentVersion, nextVersion });
          throw new Error('Migration step returned invalid database structure: expected plain object');
        }
        db = migratedDb;
        console.info('[STORAGE_MIGRATIONS] Applied migration step:', {
          fromVersion: currentVersion,
          toVersion: nextVersion
        });
      } catch (err) {
        console.error('[STORAGE_MIGRATIONS] Migration step execution failed:', { fromVersion: currentVersion, targetVersion: nextVersion, error: err });
        throw err;
      }
      db.schemaVersion = nextVersion;
      currentVersion = nextVersion;
    }
    return db;
    ```
  - Prohibit registering any identity passthrough migration (`MIGRATIONS[1] = async (db) => db;`) in production code in `src/main/library-state/migrations.ts`. In production during Ticket `01.4.3.1.1`, the dispatch table `MIGRATIONS: Record<number, (db: any, context: LibraryContext, targetPlatform?: PlatformInput) => Promise<any>>` remains strictly empty (`{}`). When `runStorageMigrations` is invoked in production against an unversioned v0 database prior to Ticket `01.4.3.1.2`, it must fail fast with `Missing migration step for schema version 1` and trip `isDegradedState = true` in `loadDB()`, protecting legacy records from corruptive down-version overwrites.
  - Export explicit test seams from `src/main/library-state/migrations.ts` for unit test isolation:
    ```typescript
    export function registerMigrationForTest(
      version: number,
      fn: (db: any, context: LibraryContext, targetPlatform?: PlatformInput) => Promise<any>
    ): () => void {
      MIGRATIONS[version] = fn;
      return () => {
        delete MIGRATIONS[version];
      };
    }

    export function resetMigrationsForTest(): void {
      for (const key of Object.keys(MIGRATIONS)) {
        delete MIGRATIONS[Number(key)];
      }
      Object.assign(MIGRATIONS, BASELINE_MIGRATIONS);
    }
    ```

### 2. Storage Lifecycle Isolation at Bootstrap (`src/main/library-state/index.ts`)
- In `createLibraryState(options: LibraryContext)`:
  - In `isDegraded()`:
    - Report `isDegradedState` whenever either `options.dbFilePath` or `options.loadDB` is provided (`if (!options.dbFilePath && !options.loadDB) return false; return isDegradedState;`), replacing the `if (!options.dbFilePath) return false;` short-circuit so instances seeded via `options.loadDB` accurately report degraded transitions to `state.isDegraded()` callers and `context.isDegraded?.() === true` action/config guards.
  - In `persistDbDirectly(db: any)`:
    - If `isDegraded()` evaluates to `true`, log structured console warning and fail fast by throwing an Error:
      ```typescript
      if (isDegraded()) {
        console.warn('[LIBRARY_STATE] Persistence aborted: database is in DEGRADED state.', { dbFilePath: options.dbFilePath });
        throw new Error('Database is in degraded state');
      }
      ```
      ensuring that `state.saveDB` and all storage write invocations reject deterministically upon degraded state, satisfying the contract expected by `tests/library-state.test.js:510`.
  - In `loadDB()`:
    - Maintain a monotonic counter `let migrationFailureEpoch = 0;` initialized in `createLibraryState` alongside `isDegradedState`. Synchronously at the entry of `loadDB()` (before awaiting `options.fs.stat`, `readJsonWithRetry`, or `options.loadDB`), capture `const failureEpochAtEntry = migrationFailureEpoch;`.
    - Uniformly wrap database retrieval whether provided via injected `(options as any).loadDB` or default file reader `readJsonWithRetry(options.dbFilePath)`.
    - Do NOT assign `cachedDb = data` immediately upon reading from `readJsonWithRetry` or `options.loadDB` before plain-object validation, `initialVersion <= CURRENT_SCHEMA_VERSION` verification, and migration completion. Preserve any pre-existing healthy `cachedDb` snapshot unmodified when entering degraded state (`cachedDb` remains `null` on cold-start `ENOENT` or initial read failure, or retains the last known healthy database object from an earlier valid read/write).
    - If `options.fs.stat` or `readJsonWithRetry` throws `ENOENT` (fresh application install), return canonical root database envelope pre-anchored at `CURRENT_SCHEMA_VERSION`:
      ```typescript
      if (err?.code === 'ENOENT') {
        isDegradedState = false;
        return {
          schemaVersion: CURRENT_SCHEMA_VERSION,
          config: normalizeLibraryConfigShape({}, targetPlatform),
          games: {}
        };
      }
      ```
    - Whenever a current read attempt fails due to a zero-byte file (`stats?.size === 0`) or a non-`ENOENT` file read failure (`readJsonWithRetry` throwing JSON `SyntaxError`, `EACCES`, `EPERM`, `EIO`), set `isDegradedState = true` and emit structured diagnostic error logging:
      `console.error('[LIBRARY_STATE] Storage load failed, entering degraded state:', { dbFilePath: options.dbFilePath, reason: stats?.size === 0 ? 'zero-byte-file' : 'read-error', error: err });`
      before returning `cachedDb || {}`.
    - Strictly validate parsed database `data` from a successful read attempt: if `data` is not an `ENOENT` fresh install and fails plain object validation (`!data || typeof data !== 'object' || Array.isArray(data)`), immediately trip `isDegradedState = true`, log structured diagnostic error:
      `console.error('[LIBRARY_STATE] Storage load failed, entering degraded state: invalid root database structure: expected plain object', { dbFilePath: options.dbFilePath });`
      and return `cachedDb || {}` to authoritatively trip the circuit breaker without overwriting `cachedDb`.
    - When the current read attempt yields a valid plain-object JSON payload (`data && typeof data === 'object' && !Array.isArray(data)`):
      - Check `const initialVersion = data.schemaVersion ?? 0;`.
      - If `initialVersion > CURRENT_SCHEMA_VERSION`:
        - Immediately log structured diagnostic error:
          ```typescript
          console.error('[STORAGE_MIGRATIONS] Database schema version is newer than supported version, entering degraded state:', {
            dbFilePath: options.dbFilePath,
            databaseVersion: initialVersion,
            maxSupportedVersion: CURRENT_SCHEMA_VERSION
          });
          ```
        - Trip the database circuit breaker: `isDegradedState = true;`.
        - Return `cachedDb || data` to immediately freeze mutative persistence across all domain actions and prevent down-version data corruption without overwriting `cachedDb`.
      - If `initialVersion === CURRENT_SCHEMA_VERSION`:
        - Reset `isDegradedState = false` to transition the state machine from `DEGRADED` back to `HEALTHY` upon reading a valid canonical database payload, assign `cachedDb = data;`, and return `data`.
      - If `initialVersion < CURRENT_SCHEMA_VERSION`:
        - Synchronize migration task execution using an isolated single-flight promise (`let inFlightMigration: Promise<LibraryDatabase> | null = null;` decoupled from the facade's action `serializedQueue` to prevent reentrancy deadlocks, clearing `inFlightMigration = null;` via an outer `.finally()` callback attached to the promise reference with an explicit `.catch(() => {})` unhandled rejection sink and conditional reference check `if (inFlightMigration === migrationPromise) inFlightMigration = null;`) with `migrationFailureEpoch` tracking and double-checked locking:
          1. First, check `if (inFlightMigration !== null) return await inFlightMigration;` *before* mutating `isDegradedState` so concurrent callers join the active migration task directly.
          2. Next, evaluate the double-checked lock: `if (migrationFailureEpoch !== failureEpochAtEntry || (cachedDb && (cachedDb.schemaVersion ?? 0) >= CURRENT_SCHEMA_VERSION)) return cachedDb || data;`. If a concurrent caller wakes up after a preceding task has failed migration (`migrationFailureEpoch !== failureEpochAtEntry`) or completed migration (`(cachedDb.schemaVersion ?? 0) >= CURRENT_SCHEMA_VERSION`), immediately abort migration execution without attempting secondary migrations.
          3. If still unmigrated, assign `const migrationPromise = (async () => { ... })(); inFlightMigration = migrationPromise;` and attach an outer cleanup chain `migrationPromise.finally(() => { if (inFlightMigration === migrationPromise) { inFlightMigration = null; } }).catch(() => {});`: capture an immutable snapshot of category state before executing `runStorageMigrations` (via `JSON.parse(JSON.stringify(rawCat))` if `context.categoryState?.loadCategoryState` is present); execute `data = await runStorageMigrations(data, context, options.targetPlatform);`, strictly reset `isDegradedState = false;` after `runStorageMigrations` resolves successfully and immediately prior to `persistDbDirectly` execution, atomically persist migrated database to disk via `await persistDbDirectly(data);`, log structured completion info (`console.info('[STORAGE_MIGRATIONS] Successfully completed and persisted storage migrations:', { fromVersion: initialVersion, currentVersion: data.schemaVersion });`), update `cachedDb = data;`, and return `data`. On rejection (`catch (err)`), execute secondary category rollback via `await context.categoryState.saveCategoryState(catStateSnapshot)` inside an isolated `try ... catch` error boundary (logging structured error `console.error('[STORAGE_MIGRATIONS] Secondary category rollback failed:', { rollbackErr, originalError: err })` if rollback fails) before logging structured diagnostics (`console.error('[STORAGE_MIGRATIONS] Migration runner failed, entering degraded state:', { initialVersion, targetVersion: CURRENT_SCHEMA_VERSION, error: err })`), authoritatively re-set `isDegradedState = true`, increment `migrationFailureEpoch++`, and return `cachedDb || data` to authoritatively trip the application circuit breaker without overwriting `cachedDb`. Ensuring cleanup is attached via outer `.finally()` guarantees synchronous mocks/test fixtures execute assignment prior to callback execution without overwriting `inFlightMigration`, while the `.catch(() => {})` sink suppresses unhandled rejections on the detached promise chain, and callers awaiting `inFlightMigration` safely receive the resolved degraded database payload `cachedDb || data` (tripping their `isDegraded()` checks) without unhandled exceptions crashing the host process.
    - Return authoritative canonical database with `schemaVersion: 1`.
  - Guarantee migrations execute exclusively during storage initialization at application bootstrap, before domain services, scanners/loaders, IPC controllers, or UI components mount.
