# 02.4.1 — Folder Section Reorder Animation Coordinator ($B$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Implement the dedicated 3-step section reorder animation coordinator `animateFolderSectionReorder` in pure headless module `src/renderer/library/section-reorder-coordinator.ts` accepting injected DOM query, state, timing, and moved path parameters for 100% headless testability in Vitest:
1. Defensive CSS escape helper:
   ```typescript
   export const safeEscapePath = (p: string) =>
     typeof CSS !== 'undefined' && typeof CSS.escape === 'function'
       ? CSS.escape(p)
       : p.replace(/(["\\])/g, '\\$1');
   ```
   used when resolving `[data-folder-path="${safeEscapePath(movedPath)}"]` to prevent `ReferenceError: CSS is not defined` in headless Node / Vitest environments.
2. Target Section Resolution:
   - Accept injected `options.movedPath?: string`. If provided, query `[data-folder-path="${safeEscapePath(options.movedPath)}"]` directly to resolve the target moving element.
   - If `movedPath` is omitted, fall back to boundary displacement array diffing between `oldOrder` and `newOrder` to infer the single moved path: find first differing index `start` (`oldOrder[start] !== newOrder[start]`) and last differing index `end` (`oldOrder[end] !== newOrder[end]`). If `oldOrder[start] === newOrder[end]`, the relocated item is `oldOrder[start]` (rightward displacement); if `oldOrder[end] === newOrder[start]`, the relocated item is `newOrder[start]` (leftward displacement). Prohibit naive `find()` which misidentifies shifted neighbors on rightward moves.
3. Configurable timing seams: default durations derived from `options.timing ?? { collapseMs: 280, glideMs: 340, expandMs: 280 }`. If any step duration is configured <= 0 (e.g. `collapseMs <= 0`, `glideMs <= 0`, `expandMs <= 0`) or executed in environments lacking CSS transition support, immediately bypass awaiting `transitionend` / `Animation.finished` events for that step and resolve immediately, preventing asynchronous test suite hangs in headless Vitest.
4. Guard clauses (instantaneous 0ms resolution):
   - Concurrency guard: if an animation is already in flight (`isReordering === true`), resolve immediately (0ms early return `if (isReordering) return;`) to prevent concurrent transition conflicts. Export `_resetReorderLockForTesting(): void` to guarantee test harness isolation in `afterEach` hooks.
   - Identity & length mismatch order guard: if `oldOrder.length === newOrder.length && oldOrder.every((p, i) => p === newOrder[i])` or if target moved path cannot be resolved, resolve immediately (0ms) without querying DOM or manipulating classes. If `oldOrder.length !== newOrder.length`, immediately bypass FLIP glide animations (0ms), commit physical DOM reordering within `options.container` to match `newOrder` immediately, and resolve (0ms), preventing out-of-bounds indexing errors during array diffing.
   - Reduced motion guard: if `options.prefersReducedMotion ?? (typeof window !== 'undefined' && typeof window.matchMedia === 'function' ? window.matchMedia('(prefers-reduced-motion: reduce)').matches : false)`, bypass all transitions (0ms), physically reorder the `.library-section` DOM elements within `options.container` to match `newOrder` immediately, and resolve.
   - Already-collapsed section guard: if the target section is already collapsed prior to reordering (`options.isCollapsed?.(targetPath) === true`), skip step 1 collapse (0ms).
    - View mode guard: if the active tab is not `'all'` (`options.activeTabId && options.activeTabId !== 'all'`), bypass section animation entirely and resolve immediately (0ms).
     - Missing container or target section guard: if `!options?.container` or if the target section element cannot be resolved in `options.container` (e.g. during headless testing or before sections finish rendering), bypass transitions (0ms); if `options?.container` exists, log structured diagnostic warning `console.warn('[SECTION_REORDER_COORDINATOR] Target section not found in container, bypassing animation:', { movedPath, selector: sectionSelector });`, physically reorder sibling `.library-section` DOM elements within `options.container` to match `newOrder` immediately, and resolve immediately (0ms) without throwing an error.
5. Concurrency & Re-Entrancy Locking:
   - While `animateFolderSectionReorder` is executing, manage an internal `isReordering` lock to prevent concurrent transition conflicts. Note that pointer interaction locking on `#shelf-tabs-wrapper` is held authoritatively by the caller (`createShelfTabsController`), and interaction locking on `refs.gameGridWrapper` is held authoritatively by `createLibraryGridController`, both spanning both `onTabReorder` animation and `updateLibraryConfig` persistence; `animateFolderSectionReorder` coordinates transitions and cleans up element styles in `finally`, but does NOT clear `options.container.style.pointerEvents` or `options.tabsWrapper.style.pointerEvents` upon animation completion.
   - Environment-safe animation frame scheduler: implement scheduler seam `const scheduleFrame = options?.scheduleFrame ?? (typeof requestAnimationFrame === 'function' ? requestAnimationFrame : (cb: () => void) => queueMicrotask(cb));` ensuring safe execution in headless Node / Vitest environments without browser globals.
    - Mandatory `try ... catch ... finally` teardown: Wrap the entire 3-step sequence and DOM resolution in a `try ... catch ... finally` block, catching and logging unexpected step failures with structured diagnostic context (`console.error('[SECTION_REORDER_COORDINATOR] Section reorder animation failed:', { movedPath, step, error: err })`) before rethrowing, tracking all modified DOM elements (both target section and all displaced sibling sections), and guaranteeing that re-entrancy lock release and element styling teardown (removing `.section-moving` class and unconditionally resetting inline `transform`, `transition`, `position`, and `z-index` styles across ALL affected section elements) occur unconditionally in `finally { targetSection?.classList.remove('section-moving'); for (const el of affectedSections) { el.style.transform = ''; el.style.transition = ''; el.style.position = ''; el.style.zIndex = ''; } isReordering = false; }` even if DOM calculations throw or an unhandled rejection occurs. Note that missing DOM elements or containers degrade gracefully under guard clauses to 0ms resolution without throwing, reserving `throw` strictly for unexpected runtime faults so valid configuration persistence is never spurious rolled back.
6. 3-step sequence:
   - Step 1: Smooth collapse of active section (if previously open). Before initiating Step 1 collapse and Step 2 DOM re-insertion, check if `document.activeElement` is contained within the moving section (`targetSection?.contains(document.activeElement)`); if so, programmatically transfer focus to a stable visible element (such as the target section's header button or corresponding shelf tab) to prevent focus eviction to `document.body`. Transition completion is synchronized using native platform `transitionend` event listeners on the collapsing container or Web Animations API `Animation.finished` promises with once-only triggers, rather than imperative `setTimeout` or `setInterval` timer shims. If `timing.collapseMs <= 0`, skip awaiting transition events and advance immediately.
   - Step 2: FLIP `translateY` glide to new position. Explicitly attach `.section-moving` CSS class to the target moving section element and elevate its local stacking context (declaring `position: relative` alongside `z-index: var(--zIndex-section-moving, 10)`, referencing design token defined in `src/styles/theme.css`) during the glide phase to provide visual feedback and prevent clipping under adjacent sibling section borders. Batched Layout Measurement Contract: The coordinator must strictly separate layout measurement reads from style writes:
     1. Batch Read (First): Capture initial bounding rects (`getBoundingClientRect()` / `offsetTop`) for the moving section and all displaced sibling sections in a single contiguous measurement pass.
     2. Batch DOM Mutation: Apply DOM order changes (node reordering in parent container).
     3. Batch Read (Last): Capture post-mutation target positions in a second contiguous measurement pass.
     4. Batch Invert & Play: Compute displacement vectors (`deltaY = first.top - last.top`) and apply inverse transforms (`transform: translateY(...)`) in a single batch. In the Play phase, prevent same-frame style coalescing: when using CSS transitions (`transitionend`), the coordinator applies inverse transforms synchronously in the invert phase and schedules transition activation (`transition: transform ...; transform: none;`) on the subsequent animation frame via injected `scheduleFrame` (or `requestAnimationFrame`), allowing the browser layout engine to register the initial transform and reliably fire `transitionend`; when using Web Animations API (`element.animate(...)`), the coordinator passes keyframes directly (`[{ transform: 'translateY(' + deltaY + 'px)' }, { transform: 'none' }]`) and awaits `Animation.finished`, executing composited transitions without style coalescing or forced reflow penalties. Interleaving DOM layout reads and style writes across sibling section loops is strictly prohibited.
     Zero-displacement guard: For any section where `Math.abs(deltaY) < 1` (or if `timing.glideMs <= 0`), immediately bypass awaiting `transitionend` / `Animation.finished` for that section and advance immediately, preventing infinite promise hangs in browser layout engines on zero-displacement transforms. Transition completion is synchronized via native `transitionend` events or `Animation.finished` promises.
   - Step 3: Re-expand if previously open. Synchronized via native `transitionend` event listeners or `Animation.finished` promises before releasing states. If `timing.expandMs <= 0`, skip awaiting transition events and advance immediately.
    - Prohibit imperative `setTimeout` or `setInterval` timer chains for driving step transitions, ensuring event listeners are cleaned up upon early abort or rejection in the mandatory `finally` block. Every transition promise (`transitionend` event or `Animation.finished` promise) must race against a bounded safety watchdog timer `(timingMs + (timing.watchdogPaddingMs ?? 100))`. The transition watchdog race helper must explicitly clear the watchdog timer via `clearTimeout(timerId)` when the transition event resolves first, and conversely invoke `removeEventListener` (or abort controller / cancel animation) when the watchdog timer expires first. If the watchdog timer triggers before the transition event (e.g. 0px height displacement, background tab throttling, or canceled transition), emit a structured warning:
      ```typescript
      console.warn('[SECTION_REORDER_COORDINATOR] Transition step timed out, forcing advancement:', {
        step,
        movedPath,
        expectedDuration: timingMs
      });
      ```
      and force resolution of the step promise so that animation advances, cleanup executes, and interaction locks are released.
    - Upon animation completion, Step 3 completion strictly cleans up inline style overrides (`transform`, `transition`, `position`, `z-index`) across all affected elements (target section and all displaced sibling sections) and removes the `.section-moving` class without repeating physical DOM re-insertion (which was already performed in Step 2's Batch DOM Mutation pass), committing the new folder order without visual flicker or redundant layout reflows.

Provide comprehensive Vitest unit tests in `src/renderer/library/section-reorder-coordinator.test.ts`.
