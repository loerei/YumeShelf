# 01.5.1 — Main Process Backward Compatibility Adapters ($S$)

## Epic
PRD: Move Headless Icon Extraction to @yumeshelf/engine

## What to build
Update the Main Process icon pipeline modules in `src/main/icon-pipeline/` to serve as thin backward-compatibility adapters delegating to `@yumeshelf/engine`. This ensures existing callers, IPC controllers, and test suites (`tests/pe-resource-decoder.test.js`, `tests/icon-pipeline-local-image.test.js`) continue working seamlessly without any interface regressions.
- In `src/main/icon-pipeline/pe-resource-decoder.ts`: Re-export `ExtractedPeIcon`, `PeVersionMetadata`, `PeResourceDecoderOptions`, `PeResourceSection` from `@yumeshelf/engine`. Re-export and delegate `PeResourceDecoder`, `extractPeIcon`, and `extractPeMetadata` to `@yumeshelf/engine`.
- In `src/main/icon-pipeline/desktop-entry.ts`: Re-export synchronous functions `findDesktopEntryIcon`, `resolveDesktopIconPath`, and `parseDesktopFileIcon` delegating to `@yumeshelf/engine`. Expose asynchronous convenience wrappers `findDesktopEntryIconAsync` and `resolveDesktopIconPathAsync` delegating to engine async implementations.
- In `src/main/icon-pipeline/service.ts`: Re-export synchronous `findLocalGameImage` (returning `LocalGameImageResult | null`), `getImageMimeType`, `LOCAL_IMAGE_CANDIDATE_PATTERNS`, `LOCAL_IMAGE_EXTENSIONS`, and `LocalGameImageResult` from `@yumeshelf/engine`.
