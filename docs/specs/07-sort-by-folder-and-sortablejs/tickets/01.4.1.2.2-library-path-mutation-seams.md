# 01.4.1.2.2 — Library Path Mutation Seams & Storage Canonicalization ($S$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Symmetrically normalize path lookups in `src/main/library-state/config.ts` across all path mutation routines using `normalizePathForPlatform(p, targetPlatform)` to prevent case or slash format mismatches from silently breaking mutations or injecting duplicates, and verify `if (context.isDegraded?.() === true)` immediately at entry of `setupLibrary`, `removeLibraryPath`, `changeLibraryPath`, and `addLibraryPath` throwing `new Error('Database is in degraded state')` before opening directory picker dialogs, mutating `config.libraryPaths`, pruning/migrating aliases, or invoking canonicalization:

- In `setupLibrary(context: LibraryContext, type: 'default' | 'custom', targetPlatform?: PlatformInput)`: check `if (context.isDegraded?.() === true) throw new Error('Database is in degraded state');` immediately at entry. Resolve `nextLibraryPath` from `defaultGamesDir` or `dialog.showOpenDialog`. Reject filesystem root boundaries (`/` on POSIX, `^[A-Za-z]:[/\\]?$` on Windows) with structured warning `console.warn('[SECURITY][CONFIG] Blocked configuration of filesystem root as library path:', { targetPath: nextLibraryPath });` and throw an Error to prevent systemic OS directory subsumption and scanner resource exhaustion. Inside `persistTask`, before `await saveFn(db)`, invoke `await canonicalizeStoredGames(db, context.categoryState, nextConfig.libraryPaths, targetPlatform)` from `./migrations` to align existing records with the newly configured library root.
- In `removeLibraryPath(context: LibraryContext, targetPath: string, targetPlatform?: PlatformInput)`: check `if (context.isDegraded?.() === true) throw new Error('Database is in degraded state');` immediately at entry. Locate the index using `config.libraryPaths.findIndex(p => normalizePathForPlatform(p, targetPlatform) === normalizePathForPlatform(targetPath, targetPlatform))`. If `index === -1 || config.libraryPaths.length <= 1`, return `config` immediately without mutating `libraryPaths`, deleting aliases, running canonicalization, or writing to disk. Otherwise, execute `config.libraryPaths.splice(index, 1)` first. In accordance with the Orphaned Folder Alias Lifecycle Invariant, retain `config.folderAliases` mappings as persistent bookmarks/tombstones even when a folder path is removed from `libraryPaths` (avoiding premature alias deletion or pruning so user customizations are restored if the path is re-added), and invoke `await canonicalizeStoredGames(db, context.categoryState, config.libraryPaths, targetPlatform, { purgeOrphans: true })` from `./migrations` (leveraging Set pre-indexing of surviving contained game records to eliminate quadratic scans during orphan category purging) to purge records in `db.games` whose `folderPath` is no longer subsumed by any remaining path in `config.libraryPaths`, remove their corresponding category assignments via `loadCategoryState()` and `saveCategoryState()` on `CategoryStateService`, re-key stored games, and migrate category IDs for newly promoted canonical roots before committing `db` via `await saveFn(db)`.
- In `changeLibraryPath(context: LibraryContext, oldPath: string, targetPlatform?: PlatformInput)`: check `if (context.isDegraded?.() === true) throw new Error('Database is in degraded state');` immediately at entry. Opens `dialog.showOpenDialog` (or uses an injected path selection seam `folderPickerSeam?: (options: any) => Promise<string[] | undefined>` on `LibraryContext` in test environments) to acquire the replacement path. If selected, reject filesystem root boundaries (`/` on POSIX, `^[A-Za-z]:[/\\]?$` on Windows) with structured warning `console.warn('[SECURITY][CONFIG] Blocked configuration of filesystem root as library path:', { targetPath: chosenPath });` and throw an Error to prevent systemic OS directory subsumption and scanner resource exhaustion. Check self-selection: if `normalizePathForPlatform(chosenPath, targetPlatform) === normalizePathForPlatform(oldPath, targetPlatform)`, return `config` immediately as a no-op without mutations. If `chosenPath` matches a *distinct* existing configured path (`normalizePathForPlatform(p, targetPlatform) === normalizePathForPlatform(chosenPath, targetPlatform) && normalizePathForPlatform(p, targetPlatform) !== normalizePathForPlatform(oldPath, targetPlatform)`), prune the old path entry instead of creating a duplicate entry (or reject if it would leave the library empty). If not already present, locate the index using `config.libraryPaths.findIndex(p => normalizePathForPlatform(p, targetPlatform) === normalizePathForPlatform(oldPath, targetPlatform))`; replace with the chosen path, canonicalize both `oldPath` and `chosenPath` via `normalizePathForPlatform(p, targetPlatform)`, and migrate all folder alias keys subsumed by `oldPath` (`isSubsumedBy(aliasKey, canonicalOldPath, targetPlatform)`) by forming the new key via segment-safe replacement: if `aliasKey === canonicalOldPath`, `newKey = canonicalNewPath`; otherwise, extract the relative subpath via segment slicing accounting for root trailing slashes (`const subpath = aliasKey.slice(canonicalOldPath.endsWith('/') ? canonicalOldPath.length : canonicalOldPath.length + 1); const newKey = subpath ? (canonicalNewPath.endsWith('/') ? `${canonicalNewPath}${subpath}` : `${canonicalNewPath}/${subpath}`) : canonicalNewPath;`), normalizing it via `normalizePathForPlatform(newKey, targetPlatform)`, validating against prototype pollution keys (`__proto__`, `constructor`, `prototype`), deleting the old key via `delete config.folderAliases[aliasKey]`, and storing `config.folderAliases[canonicalNewKey]` (pruning any not subsumed by remaining configured roots). After updating `config.libraryPaths`, invoke `await canonicalizeStoredGames(db, context.categoryState, config.libraryPaths, targetPlatform)` from `./migrations` to re-key stored games and migrate category IDs for newly subsumed roots before committing `db` via `await saveFn(db)`.
- In `addLibraryPath(context: LibraryContext, targetPlatform?: PlatformInput)`: check `if (context.isDegraded?.() === true) throw new Error('Database is in degraded state');` immediately at entry. Opens `dialog.showOpenDialog` (or uses an injected path selection seam `folderPickerSeam?: (options: any) => Promise<string[] | undefined>` on `LibraryContext` in test environments) to acquire the path. If selected, reject filesystem root boundaries (`/` on POSIX, `^[A-Za-z]:[/\\]?$` on Windows) with structured warning `console.warn('[SECURITY][CONFIG] Blocked configuration of filesystem root as library path:', { targetPath: chosenPath });` and throw an Error to prevent systemic directory subsumption and scanner resource exhaustion. Check for duplicates using `config.libraryPaths.some(p => normalizePathForPlatform(p, targetPlatform) === normalizePathForPlatform(chosenPath, targetPlatform))` before appending. After updating `config.libraryPaths`, invoke `await canonicalizeStoredGames(db, context.categoryState, config.libraryPaths, targetPlatform)` from `./migrations` to re-key stored games and migrate category IDs for newly subsumed roots before committing `db` via `await saveFn(db)`.

Wrap `canonicalizeStoredGames` and `saveFn(db)` in `setupLibrary`, `removeLibraryPath`, `changeLibraryPath`, and `addLibraryPath` within an explicit error boundary logging `console.error('[LIBRARY_STATE][CONFIG_MUTATION] Failed to persist library path mutation:', { action, targetPath, error: err })` before re-throwing, and log diagnostic warning `console.warn('[LIBRARY_STATE][REMOVE_PATH] Cannot remove library path: path not found or minimum root count reached', { targetPath, configuredCount: config.libraryPaths.length })` when `removeLibraryPath` no-ops.

Author comprehensive Vitest unit tests in `src/main/library-state/config.test.ts`.
