# 08.1.1 — Task Parameter Interpolation & Stream Parser Engine

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The standalone parameter interpolation engine (`src/main/addons/task-argument-parser.ts`) and line-buffered stdout progress stream parser (`src/main/addons/task-stream-parser.ts`) supporting `json-stream`, `percent`, and `regex` formats.

## Explicit Assumptions & Boundaries
- Pure algorithmic modules decoupled from OS child process spawning and Electron IPC channels.
- Secret Sanitization: Decrypted credentials resolved from `CredentialVaultService` are tracked to enable string redaction in logs and events.

## Blocked by
- 01.1.2 — Manifest Registry and Multi-Tag Search Index

## Status
ready-for-agent

## Acceptance criteria
- [ ] Implement parameter parser `interpolateTaskArguments(actionSpec: AddonActionSpec, userInputs: Record<string, any>, config: Record<string, any>, context: TaskContext): { args: string[]; env: Record<string, string> }` in `src/main/addons/task-argument-parser.ts`:
  - Validates string length bounds on user text inputs (max 2048 characters) to prevent buffer bloat.
  - Precedence: `Built-in Variables ({gameDir}, {exePath}, {gameKey}, {addonDir}, {entryPoint}) > Action InputSchema Values > Tool ConfigSchema Values`.
  - Validate required variables prior to execution; cleanly prune optional empty placeholders without leaving unresolved `{var}` tokens or empty string arguments (`""`).
  - Maps sensitive credentials from `manifest.credentialsSchema` exclusively into the `env` object (using `field.envVar || 'YUMESHELF_CREDENTIAL_' + field.key.toUpperCase()`) or stdin payload, NEVER interpolating decrypted credentials into CLI argument arrays (`args`).
- [ ] Implement credential redaction utility replacing all resolved credential values with `[REDACTED]` for safe logging and IPC broadcasting.
- [ ] Implement line-buffered progress stream parsers in `src/main/addons/task-stream-parser.ts`:
  - Buffer stdout stream chunks with `readline` interface or carryover buffer to ensure complete line delivery before parsing.
  - `json-stream`: Parse newline-delimited JSON objects (e.g. `{"percent": 45, "step": "Map005.json", "message": "Translating dialogues"}`).
  - `percent`: Parse percentage strings (e.g. `45%`, `Progress: 0.45`).
  - `regex`: Custom regex extraction from CLI output.
- [ ] Unit tests verifying parameter precedence, input length bounds, empty token pruning, secret redaction, chunk boundary splitting (single JSON object split across multiple `data` events), concatenated multi-line burst parsing, and error recovery across all 3 parser modes.
- [ ] Execute automated unit tests via `npm run test:node -- tests/task-stream-parser.test.js`.
