# 06.2 — Add-on Transactional Rollback & Crash Recovery

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The crash recovery sweep mechanism in `AddonLifecycleService` on app startup (`app.whenReady()`), pre-launch lock checks in `onBeforeLaunch`, recovering both `'deploying'` and `'active'` session states, restoring `.yumeshelf-bak` backups, and atomic session lock unlinking.

## Explicit Assumptions & Boundaries
- If YumeShelf, the OS, or the game crashes mid-session or mid-copy, the game directory is guaranteed to be restored to vanilla on next application launch or before the next game launch.
- Non-recursive directory unlinking catches and ignores `ENOTEMPTY` / `EEXIST` to preserve user mod logs and runtime caches.

## Blocked by
- 06.1.2 — Add-on Shim Deployment & Reversion Engine

## Status
ready-for-agent

## Acceptance criteria
- [ ] Implement `recoverCrashedSessions(targetDirs?: string[])` sweep running automatically on app startup (`app.whenReady()`) or accepting `targetDirs?: string[]` (or injectable `getGameDirectories` provider) for isolated fixture testing:
  - Scan game directories with existing `.yumeshelf-session.json` lockfiles.
  - Parse session lockfile safely wrapped in try/catch. If JSON parse error occurs, trigger fallback directory scan restoring all `*.yumeshelf-bak` files.
  - Validate all target paths resolve strictly within `gameDir` before file operations.
  - Delete any deployed or partially copied shim files recorded in `.yumeshelf-session.json`.
  - Restore all recorded original files from `.yumeshelf-bak` backups.
  - Safely unlink empty created directories in reverse depth-first order, catching and ignoring `ENOTEMPTY` / `EEXIST` errors to preserve user mod runtime logs/caches.
  - Delete stale `.yumeshelf-session.json`.
- [ ] Integrate pre-launch recovery check into `AddonLifecycleService.onBeforeLaunch()`: if a game directory has a stale `.yumeshelf-session.json` prior to launch, execute immediate transactional rollback before proceeding with new shim deployment.
- [ ] Integration tests with synthetic crash fixtures simulating mid-copy interruption (`status: 'deploying'`), abrupt process termination (`status: 'active'`), pre-existing `*.yumeshelf-bak` stale backup conflict handling, and corrupted/truncated `.yumeshelf-session.json` (0-byte or syntax error), verifying complete restoration of vanilla game files via fallback directory scan, backup restoration, mod log preservation, and stale lockfile deletion.
- [ ] Execute automated tests via `npm run test:node -- tests/addon-lifecycle.test.js` or `npm run test:node -- tests/crash-recovery.test.js`.
