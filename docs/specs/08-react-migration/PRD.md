# PRD: React Migration & Renderer Reconstruction

## 1. Overview & Objective

Completely reconstruct YumeShelf's renderer from raw imperative DOM manipulation and untyped JavaScript to a modern, declarative React 19 architecture, eliminating 100% of frontend technical debt, dual-FLIP animation conflicts, listener/timer memory leaks, the 1,015-line save editor sidebar monolith, all shadow engine duplicates in the renderer, and all `// @ts-nocheck` directives across `src/`.

### Core Problem & Architectural Rationale
An exhaustive architectural audit across specialized review tracks revealed that the current renderer is in **Bad State (Preparatory Refactoring Required)**:
1. **Suppressed Type Checking**: 62 frontend files in `src/renderer/` (plus `src/renderer.ts`, `src/shared/types/ipc.d.ts`, and `src/shared/types/save-editor.d.ts`, totaling 65 files across `src/`) begin with `// @ts-nocheck`. The frontend is effectively untyped JavaScript disguised with `.ts` extensions, leaving compiler verification disabled.
2. **Shadow Engine Duplication in Renderer**: Despite the existence of `@yumeshelf/engine`, `src/renderer/` contains zero imports of `@yumeshelf/engine`. Instead, `src/renderer/save-editor/` implemented its own parallel shadow engine layer (`data-engine.ts` plus 7 custom engine files in `src/renderer/save-editor/engines/`) that sniffs properties, guesses engine types, and recursively traverses objects in client-side JavaScript. This violates the Single Source of Truth invariant in [`AGENTS.md`](file:///d:/Projects/YumeShelf/AGENTS.md).
3. **Dual-FLIP Animation Race Condition**: Two independent, competing FLIP implementations exist simultaneously: manual CSS transform calculations in [`src/renderer/utils/flip-animation.ts`](file:///d:/Projects/YumeShelf/src/renderer/utils/flip-animation.ts) and Web Animations API calls (`captureCardRects` & `animateReorderedCards`) inside [`src/renderer/library-grid.ts`](file:///d:/Projects/YumeShelf/src/renderer/library-grid.ts). When reordering, both engines race and mutate elements concurrently.
4. **IPC State & DOM Thrashing**: [`src/renderer/events/ipc-events.ts`](file:///d:/Projects/YumeShelf/src/renderer/events/ipc-events.ts) mutates in-memory object references in place, queries the DOM with `querySelectorAll` to overwrite textContent directly, and then immediately triggers a full grid wipe and re-render via `sortGames()`. Furthermore, `bindIpcEvents` provides zero teardown/unsubscribe handles, leaking listeners.
5. **Passive State Store**: [`src/renderer/state/ui-runtime-state.ts`](file:///d:/Projects/YumeShelf/src/renderer/state/ui-runtime-state.ts) is a closure without `subscribe(listener)` or `getSnapshot()` methods, making clean integration with React 19's `useSyncExternalStore` impossible without an observable store refactoring.
6. **Static DOM Bloat & Global Listener Pollution**: [`src/index.html`](file:///d:/Projects/YumeShelf/src/index.html) embeds 500 lines of static markup for 9 separate subsystems, forcing [`src/renderer/bootstrap/dom-refs.ts`](file:///d:/Projects/YumeShelf/src/renderer/bootstrap/dom-refs.ts) to query ~150 distinct element IDs. [`src/renderer/tooltips.ts`](file:///d:/Projects/YumeShelf/src/renderer/tooltips.ts) attaches 7 permanent document/window listeners with no `destroy()` method.
7. **Save Editor Monolith & Ingress Breach**: [`src/renderer/save-editor/sidebar.ts`](file:///d:/Projects/YumeShelf/src/renderer/save-editor/sidebar.ts) contains a 922-line procedural function (`setupSidebar`) with cyclomatic complexity > 300 and 14 nesting levels. Dirty checking runs synchronous `JSON.stringify` over 5MB to 50MB saves on every keystroke, and [`src/renderer/save-editor/translator.ts`](file:///d:/Projects/YumeShelf/src/renderer/save-editor/translator.ts) executes raw `fetch()` calls to external Google Translate endpoints directly from the browser renderer.

To establish a clean, robust foundation for Epic 09 (Sort by Folder) and downstream epics, this epic executes a 2-phase reconstruction across 37 modular tickets (24 in Phase 1 and 13 in Phase 2), establishing `@yumeshelf/engine` as the sole headless engine and reducing the Renderer to 100% pure presentation.

### Coexistence Architecture During Migration
To ensure zero regression and keep `npm run typecheck` clean throughout the transition, the migration follows the `Expand -> Contract -> Delete` lifecycle:
- In Phase 1 (Tickets 01–07.1.3), new declarative React components and context providers are developed and unit-tested in isolation using in-memory Vitest harnesses while legacy procedural DOM controllers continue running the active application runtime.
- In Ticket 07.2.1, the composition root cuts over atomically: `src/renderer.ts` mounts `<App />` into `#react-root` via `createRoot`, and in Ticket 07.2.2 43 obsolete legacy procedural files are decommissioned and permanently deleted (retaining `i18n-binder.ts`, `markdown-lite.ts`, and `ui/toast-pill.ts` until Ticket 10.2 for save-editor coexistence).
- In Phase 2, Save Editor React components are constructed alongside legacy procedural save files with transitional IPC dual-envelopes in Ticket 08.2.1.1, and all 22 remaining legacy save-editor files, orphaned utilities, and shadow types are contracted and retired in Ticket 10.2 upon verified standalone React cutover in Ticket 10.1.
