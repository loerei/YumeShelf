# 01.3.2 — Library Grid SortableJS Card Drag Integration & Styles ($S$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Integrate the SortableJS drag-drop controller into the library grid lifecycle for existing flat sort modes (`date`, `played`, `az`, `custom`), execute the final cutover from native HTML5 drag listeners to SortableJS, and establish SortableJS card drag styles:
1. Add SortableJS card drag CSS classes to `src/style.css`: `.sortable-card-fallback` (referencing tokenized elevation `var(--zIndex-card-drag, 1600)` defined in `src/styles/theme.css`), `.sortable-card-ghost`, `.sortable-card-chosen`.
2. Update `createLibraryGridController` in `src/renderer/library-grid.ts` to accept injected seam `bindGrids?: (containers: HTMLElement[]) => void`, and invoke `options.bindGrids([refs.favGrid, refs.unfavGrid])` after rendering cards in flat sort modes (`date`, `played`, `az`, `custom`). In flat sort modes when `favorites.length === 0`, ensure `refs.favGrid` retains an accessible drop target container (with `.drop-zone` and `min-height: 40px`, or equivalent styling) so SortableJS can calculate pointer bounding box intersections for cross-zone card drops from `refs.unfavGrid` into favorites, symmetrically aligning with Ticket 02.4.2.2.1.1. In addition, the card drag integration and custom order reordering coordinator universally employ sibling-relative anchor resolution (identifying preceding/succeeding sibling game keys via `dataset.gameKey` in the DOM container and inserting before/after that anchor key in `customOrder`), strictly prohibiting index splices on unified `customOrder` from container-relative `evt.newIndex` across partitioned containers (`refs.favGrid` and `refs.unfavGrid`). Furthermore, incorporate focus continuity tracking across render passes: reordering and rendering passes preserve and reuse existing DOM elements keyed by stable entity identifiers (`dataset.gameKey`), updating cards in-place without unmounting active focused nodes, retaining keyboard focus throughout the operation without focus eviction to `document.body`.
3. Execute HTML5 drag cutover: Strip native HTML5 drag event listeners and attributes (`draggable`, `ondragstart`, `ondragend`, `ondragenter`, `ondragleave`, `ondragover`) from `src/renderer/game-cards.ts` and (`draggable`, `ondragstart`, `ondragend`, `ondragenter`, `ondragleave`, `ondragover`, `ondrop`) from `src/renderer/stack-cards.ts`. Remove obsolete `onDragStart` and `onDragStateReset` hooks from `commonCardCallbacks` in `src/renderer/bootstrap/app-composition.ts`, remove obsolete `dragDropGridController.attachZoneHandlers();` from the bootstrap sequence, and remove obsolete `dragPointerSlop` and `dragRowTolerance` parameters from `app-composition.ts` and `src/renderer.ts`.
4. Update `createRendererComposition` in `src/renderer/bootstrap/app-composition.ts` to instantiate `createDragDropGridController` retaining its essential runtime dependencies:
   ```typescript
    const dragDropGridController = createDragDropGridController({
      ...options.cardDragOptions,
      electronAPI,
      getActiveCategoryId: () => state.getActiveCategoryId(),
      getAllGames: () => state.getAllGames(),
      getCurrentSort: () => state.getCurrentSort(),
      setCurrentSort: (sort) => state.setCurrentSort(sort),
      isReordering: () => libraryGridController ? libraryGridController.isReordering() : false,
      refs,
      sortGames: (sort) => libraryRuntime.sortGames(sort),
      targetPlatform: options.targetPlatform
    });
   ```
5. Author initial `src/renderer/library-grid.test.ts` unit tests verifying `bindGrids` is called with `[refs.favGrid, refs.unfavGrid]` on render pass.
6. Headless runtime environment safety guards: Guard `localStorage.setItem('yumeshelf_sort_pref', type)` behind `typeof localStorage !== 'undefined'` and wrap in a `try ... catch` error boundary in `src/renderer/library-grid.ts` logging a structured error:
   ```typescript
   console.error('[LIBRARY_GRID] Failed to persist sort preference to localStorage:', {
     sortType: type,
     error: err
   });
   ```
   upon DOMException (e.g. quota exhaustion or restricted storage environments) to allow rendering to proceed uninterrupted, and guard `requestAnimationFrame` with fallback to `typeof requestAnimationFrame === 'function' ? requestAnimationFrame : queueMicrotask`, ensuring `src/renderer/library-grid.test.ts` executes deterministically in Node.js Vitest without throwing ReferenceError.

At the completion of this ticket, the migration from bespoke HTML5 drag math to SortableJS connected groups is completely operational and testable in the running application for all existing flat sort modes before proceeding to subsequent configuration and folder sorting phases.
