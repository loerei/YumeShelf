# 02.1.1 — macOS App Bundle Icon Resolution ($B$)

## Epic
PRD: Move Headless Icon Extraction to @yumeshelf/engine

## What to build
Implement macOS `.app` bundle icon resolution inside `@yumeshelf/engine` in `packages/yume-engine/src/bundle/app-bundle-inspector.ts`. Implement `findAppBundleIcon(bundlePath: string, options?: { fs?: IFileSystem; signal?: AbortSignal; maxArtworkSize?: number; maxRsrcSize?: number }): Promise<AppBundleIconResult | null>`. Detect bundle root via `resolveBundleRoot`, parse `Contents/Info.plist` via `parsePlist`, extract `CFBundleIconFile` / `CFBundleIconName` sanitizing against traversal sequences (`..`), null bytes, and path separators. Construct candidate icon paths using POSIX forward-slash concatenation (`${bundleRoot}/Contents/Resources/${iconName}` or `path.posix.join`) to prevent `ENOENT` path corruption on Windows host runners. Perform fallback directory scan of `Contents/Resources/` prioritizing well-known icon names. Dynamically derive `ext` from candidate path (`path.posix.extname(candidatePath).replace(/^\./, '').toLowerCase() || 'icns'`) returning `{ buffer, ext, path: candidatePath }`. Enforce candidate file size bounds `stat.size <= (options?.maxArtworkSize ?? options?.maxRsrcSize ?? DEFAULT_MAX_ARTWORK_SIZE)` before reading into memory. Re-export `findAppBundleIcon` from `packages/yume-engine/src/bundle/index.ts`. Add comprehensive unit test suite in `packages/yume-engine/tests/app-bundle-inspector.test.ts` using `MockFileSystemProvider`.

- Detection and resolution algorithm:
  1. Detect bundle root:
     ```typescript
     if (!bundlePath || typeof bundlePath !== 'string') return null;
     const bundleRoot = resolveBundleRoot(bundlePath) || (bundlePath.toLowerCase().endsWith('.app') ? bundlePath : null);
     if (!bundleRoot) return null;
     ```
  2. Normalize options: extract `fs` (defaulting to `NodeFileSystemProvider`), `signal`, `maxArtworkSize`, and `maxRsrcSize`.
  3. Plist parsing:
     - Check `signal?.aborted` before I/O.
     - Locate `Contents/Info.plist` inside `bundleRoot`.
     - If `Info.plist` exists, read buffer and parse using `parsePlist(plistBuffer)` wrapped inside a `try...catch` block. If `parsePlist` fails or throws on corrupted XML/bplist metadata, safely catch the exception and fall through directly to the directory scan fallback.
     - Extract `CFBundleIconFile` (or fallback `CFBundleIconName`).
     - Sanitize icon filename:
       - Reject null bytes (`\0`, `%00`) and control characters.
       - Reject forward slashes (`/`), backslashes (`\`), traversal sequences (`..`), and enforce `path.posix.basename(iconName) === iconName && path.win32.basename(iconName) === iconName`.
       - Append `.icns` extension only if `iconName` does not already have an image extension (`!/\.(icns|png)$/i.test(iconName)`).
       - Construct candidate path using POSIX forward slash concatenation:
         ```typescript
         const candidatePath = `${bundleRoot}/Contents/Resources/${iconName}`;
         ```
         (or `path.posix.join(bundleRoot, 'Contents', 'Resources', iconName)`).
       - Check if file exists via `fs.stat(candidatePath)` wrapped in a `try...catch` block; if missing (`ENOENT`) or unreadable, fall through cleanly to the directory scan fallback.
  4. Fallback directory scan:
     - If `CFBundleIconFile` is absent, invalid, or the file does not exist (or fails the pre-read size check in Step 5), perform a directory scan of `Contents/Resources/` via `fs.readdir(resourcesDir)` (guarded by `signal?.aborted`), wrapped inside a `try...catch` block to safely return `null` on missing or inaccessible `Contents/Resources` directory without throwing `ENOENT`.
     - Look for `.icns` and `.png` files, prioritizing well-known names: `icon.icns`, `appicon.icns`, `game.icns`, or the first available `.icns` / `.png` file in alphabetical order. For each candidate file encountered in the directory scan, perform a pre-read size check (`stat.size > 0 && stat.size <= maxSize`) and execute `continue` if empty or oversized to evaluate subsequent files rather than terminating the scan.
  5. File size capping:
     - Before reading the candidate into memory, check `stat.size`:
       ```typescript
       const maxSize = options?.maxArtworkSize ?? options?.maxRsrcSize ?? DEFAULT_MAX_ARTWORK_SIZE;
       if (stat.size <= 0 || stat.size > maxSize) {
         // Cleanly fall through to Step 4 directory scan fallback instead of aborting with null
         return await fallbackScanResources();
       }
       ```
  6. Read buffer:
     - Read candidate buffer via `await fs.readFile(candidatePath)` wrapped inside a `try...catch` block to cleanly fall through to Step 4 directory scan fallback if candidate file reading encounters `EACCES`, `EBUSY`, or file locking errors:
       ```typescript
       let raw: Buffer;
       try {
         raw = await fs.readFile(candidatePath);
       } catch {
         // Cleanly fall through to Step 4 directory scan fallback on read or locking errors
         return await fallbackScanResources();
       }
       ```
     - Derive `ext` dynamically from matched candidate path:
       ```typescript
       const ext = path.posix.extname(candidatePath).replace(/^\./, '').toLowerCase() || 'icns';
       return {
         buffer: Buffer.isBuffer(raw) ? raw : Buffer.from(raw),
         ext,
         path: candidatePath
       };
       ```
