# 02.1 — MultiOS Environment Paths Interface Seam in YumeEngine ($S$)

## Epic
PRD: Codebase Readiness for MultiOS Platform Support

## What to build
Extend the `IEnvironmentPaths` interface in `packages/yume-engine/src/types.ts` with optional methods `getMacApplicationSupportHome?(): string` (`~/Library/Application Support`) and `getMacPreferencesHome?(): string` (`~/Library/Preferences`). Implement these methods in `NodeFileSystemProvider` (`packages/yume-engine/src/fs/node-fs-provider.ts`) and `MockFileSystemProvider` (`packages/yume-engine/tests/fixtures/mock-fs-provider.ts`) with private field initializers. Add optional declarations to `FileSystemProvider` in `src/main/save-folder-resolver/types.ts`, implement in `DefaultFileSystemProvider` (`src/main/save-folder-resolver/fs-provider.ts`) returning empty strings if `os.homedir()` is empty/undefined to prevent relative path fallback, and in `MockFileSystemProvider` (`src/main/save-folder-resolver/fs-provider.ts`) using hermetic `this.env.get(...)` and `this.getHomeDir()` getters. Forward methods across the inline `unifiedFs` adapter in `src/main/save-folder-resolver/index.ts`.

## Explicit Assumptions & Boundaries
- Pure structural refactoring ($S$) introducing environment path abstractions without altering save discovery logic.
- Maintains 100% backward compatibility for existing Windows and Linux resolvers.
