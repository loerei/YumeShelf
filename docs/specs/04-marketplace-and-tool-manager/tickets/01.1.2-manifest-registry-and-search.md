# 01.1.2 — Manifest Registry and Multi-Tag Search Index

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The declarative `AddonRegistryService` managing add-on manifest schemas, remote catalog synchronization, offline caching (`addons.json`) with atomic write-and-replace semantics, dependency injection seams for paths and fetch, multi-tag query indexing using `@yumeshelf/engine` compatibility matching helper (`matchesEngineCompatibility`), and schema validation for both launch-bound (`shim`, `companion`, `composite`) and task-bound (`task`) add-ons.

## Blocked by
- 01.1.1 — SSRF Socket Validator & Network Security Layer
- Epic 01: YumeEngine Core Extraction & 100% F95zone PE Binary Inspector

## Status
ready-for-agent

## Acceptance criteria
- [ ] Define `AddonManifest`, `AddonStrategy` (`'shim' | 'companion' | 'composite' | 'task'`), `AddonActionSpec`, `AddonActionField`, `EngineCompatibilityRule`, and `AddonCredentialField` (including optional `envVar?: string`) TypeScript interfaces.
- [ ] Define and export `matchesEngineCompatibility(profileOrTag: GameEngineProfile | F95EngineTag | string, rule: F95EngineTag | EngineCompatibilityRule): boolean` helper in `@yumeshelf/engine` and export on `YumeEngine` facade (`packages/yume-engine/src/index.ts`).
- [ ] Implement `AddonRegistryService` loading declarative manifests from remote registry with offline local cache envelope (`addons.json` with `{ version: number, lastSyncedAt: number, addons: AddonManifest[] }`), consuming `SSRFValidator` custom socket agent or stream dispatcher for catalog synchronization (blocking private/local ranges, redirect protocol downgrades, and multi-IP rebinding). Support `AddonRegistryOptions { paths?: { addonsDir?: string, cacheFile?: string }; fetchFn?: typeof fetch; ssrfValidator?: SSRFValidator }` in constructor for headless testing.
- [ ] Implement base manifest schema validation (ID regex `/^[a-z0-9_-]{3,64}$/`, name, version, author, and category union `'translation' | 'save-editor' | 'modding' | 'utility' | 'cheat'`).
- [ ] Implement strategy-specific schema validation for `'shim'` and `'composite'` (requiring non-empty `shimFiles: string[]` where every entry is a relative POSIX path strictly contained within `userData/addons/<id>/` without leading slashes, Windows drive letters, `..` path traversals, or NTFS stream colons).
- [ ] Implement strategy-specific schema validation for `'task'`, `'companion'`, and `'composite'` (requiring non-empty relative POSIX `entryPoint` path resolving strictly within `userData/addons/<id>/` without leading slashes, Windows drive letters, or `..` path traversals).
- [ ] Implement task action schema validation for `'task'` strategy (requiring non-empty `actions: AddonActionSpec[]` array where each action defines `id`, `label`, and `argsTemplate: string[]`).
- [ ] Implement schema-level download integrity validation: if `downloadUrl` is provided in a manifest, it must strictly use the `https://` protocol and require a valid 64-character hex `sha256` integrity checksum property.
- [ ] Implement multi-tag search index and filter engine (`engine`, `variant`, `strategy`, `category`, `author`, `name`), using `@yumeshelf/engine` compatibility matching helper.
- [ ] Implement atomic write-and-replace (`.tmp` -> `fsync` -> `rename`) when saving cached catalog manifests to `userData/addons/addons.json`.
- [ ] Unit tests for manifest validation (including task action schema checking and `entryPoint` path containment), engine compatibility matching helper (including composite variant and architecture tests), HTTPS URL + SHA-256 enforcement, search filtering, atomic file write, and offline cache fallback.
- [ ] Execute automated unit tests via `npm run test:node -- tests/addon-registry.test.js`.
