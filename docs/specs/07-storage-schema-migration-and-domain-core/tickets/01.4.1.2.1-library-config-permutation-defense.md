## What to build
Update `updateLibraryConfig` in `src/main/library-state/config.ts` to accept an explicit parameter seam `targetPlatform?: PlatformInput` (with fallback to `context.targetPlatform || process.platform`), and check database health before persisting: if `context.isDegraded?.() === true`, throw `new Error('Database is in degraded state')` rather than completing normally, ensuring caller transactional `catch` blocks in `shelf-tabs.ts` and `settings.ts` trigger rollback (`onReorderFailed`, restoring DOM elements/tabs). Symmetrically update `createLibraryState` in `src/main/library-state/index.ts` to expose `targetPlatform?: PlatformInput` on `updateLibraryConfig`.

At the entry of `updateLibraryConfig`, defensively delete any legacy singular `libraryPath` from updates (`delete (updates as any).libraryPath;`) to prevent directory injection bypasses, strictly enforcing that new library root paths can only be added through `addLibraryPath` via native OS directory picker dialogs (`dialog.showOpenDialog`). Validate incoming `updates.libraryPaths` structure and element types:
```typescript
if (updates.libraryPaths !== undefined) {
  if (!Array.isArray(updates.libraryPaths) || updates.libraryPaths.length === 0 || updates.libraryPaths.some(p => typeof p !== 'string' || !p.trim())) {
    throw new Error('Invalid libraryPaths: expected non-empty array of non-empty path strings');
  }
  for (const item of updates.libraryPaths) {
    if (/\0|\r|\n/.test(item)) {
      console.warn('[SECURITY][CONFIG_PATH_INJECTION] Blocked invalid path containing illegal characters or invalid type in updateLibraryConfig:', { path: item });
      throw new Error('Invalid libraryPaths: path contains illegal characters');
    }
  }
}
```

Strictly validate incoming `updates.libraryPaths` against arbitrary system directory injection and path dropping via duplicate entries: when `updates.libraryPaths` is explicitly provided, derive `const currentConfig = normalizeLibraryConfigShape(db.config, targetPlatform);` (forwarding `targetPlatform` to ensure cross-platform path rules consistency in MultiOS environments) and verify that `updates.libraryPaths` is strictly a valid bijective permutation containing the exact same set of canonical paths as `currentConfig.libraryPaths`. To prevent false rejections when `currentConfig.libraryPaths` contains un-normalized host Windows backslashes or legacy duplicates, symmetrically normalize and deduplicate *both* arrays using `normalizePathForPlatform(p, targetPlatform)`:
```typescript
const currentCanonical = Array.from(new Set(currentConfig.libraryPaths.map(p => normalizePathForPlatform(p, targetPlatform))));
if (currentCanonical.length === 0) throw new Error('Cannot reorder empty libraryPaths configuration');
if (new Set(updates.libraryPaths.map(p => normalizePathForPlatform(p, targetPlatform))).size !== updates.libraryPaths.length) throw new Error('Duplicate libraryPaths in permutation');
const updateCanonical = Array.from(new Set(updates.libraryPaths.map(p => normalizePathForPlatform(p, targetPlatform))));
if (updateCanonical.length !== currentCanonical.length) throw new Error('Invalid libraryPaths permutation length');
if (!updateCanonical.every(p => currentCanonical.includes(p))) {
  console.warn('[SECURITY][CONFIG_PATH_INJECTION] Blocked unauthorized library path in permutation:', {
    unauthorizedPaths: updateCanonical.filter(p => !currentCanonical.includes(p)),
    configuredRoots: currentConfig.libraryPaths
  });
  throw new Error('Unauthorized libraryPath in permutation');
}
```
If `updates.libraryPaths` contains paths not present in `currentConfig.libraryPaths`, drops existing paths, contains duplicate entries, or attempts to inject arbitrary system directories, reject the update by throwing an Error (rejecting the Promise) after emitting structured security diagnostic to guarantee that callers' `catch` blocks trigger transactional rollback. When `updates.libraryPaths` is omitted (e.g. updating `folderAliases`), bypass path permutation checks.

When `updates.folderAliases` is provided in `updateLibraryConfig`, defensively validate ingress: verify `if (!isPlainObject(updates.folderAliases)) throw new Error('Invalid folderAliases: expected plain object');` (using `isPlainObject` from `src/main/library-state/scanner.ts`) before inspecting keys or evaluating boundary containment. Sanitize it against prototype pollution by validating own properties (`Object.prototype.hasOwnProperty.call`) and rejecting or stripping `__proto__`, `constructor`, and `prototype` keys prior to evaluating boundary containment. Enforce boundary containment while preserving the Orphaned Folder Alias Lifecycle Invariant: pre-index all pre-existing canonical alias keys into a `Set<string>` once prior to the alias loop (`const preExistingCanonicalKeys = new Set(Object.keys(currentConfig.folderAliases || {}).map(k => normalizePathForPlatform(k, targetPlatform)));`), eliminating $O(A^2)$ array allocations and main-thread event loop stalls. For each incoming alias key, defensively verify that `typeof key === 'string' && key.trim().length > 0`; prune or reject invalid, empty, or whitespace-only keys whose normalized representation evaluates to empty string `""`. Reject or prune any alias key containing illegal control characters or null-bytes (`/\0|\r|\n/`), emitting structured security warning `console.warn('[SECURITY][CONFIG_ALIAS_INJECTION] Blocked folder alias key containing illegal characters:', { key });` before boundary containment checks. Canonicalize each valid incoming alias key via `const canonicalKey = normalizePathForPlatform(key, targetPlatform)` and check existence via `const isPreExisting = preExistingCanonicalKeys.has(canonicalKey);`. Boundary containment validation via `isSubsumedBy(canonicalKey, root, targetPlatform)` against `currentConfig.libraryPaths` MUST ONLY evaluate newly introduced alias keys (`!isPreExisting`). Pre-existing alias keys already present in `currentConfig.folderAliases` MUST be exempted from active library root containment checks to preserve durable tombstones when paths have been removed. Any newly introduced alias key falling outside configured library roots MUST be rejected by throwing an Error (`throw new Error('Unauthorized folder alias key outside library roots')`) to trigger caller transactional rollback across `shelf-tabs.ts` and `settings.ts`, while logging structured security diagnostic:
```typescript
console.warn('[SECURITY][CONFIG_ALIAS_INJECTION] Blocked unauthorized folder alias key outside library roots:', {
  aliasKey: canonicalKey,
  configuredRoots: currentConfig.libraryPaths
});
```
strictly enforcing the identical boundary defense required by `setFolderAlias` in ticket `01.4.2.2`. Deep-merge folder aliases: when constructing `sanitizedUpdatesAliases` from `updates.folderAliases`, index each valid entry under its canonical normalized key `const canonicalKey = normalizePathForPlatform(key, targetPlatform)` (guarding against empty strings and prototype pollution keys `['__proto__', 'constructor', 'prototype']`) prior to merging `{ ...(currentConfig.folderAliases || {}), ...sanitizedUpdatesAliases }` (or explicitly deleting `canonicalKey` from the merged alias map when the incoming alias value is empty or whitespace-only `""`), ensuring that caller-supplied non-canonical key casing or backslash variations (e.g. `{ 'D:\\Games\\Sub': '' }`) overwrite the existing canonical key (`'d:/games/sub'`) in `currentConfig.folderAliases` so `normalizeLibraryConfigShape(mergedConfig, targetPlatform)` cleanly prunes cleared aliases while preserving pre-existing aliases and durable tombstones under partial update payloads. If database persistence rejects during configuration mutation, the catch block MUST log a structured error via `console.error('[LIBRARY_STATE][CONFIG_UPDATE] Failed to persist configuration updates:', { updates, error: err })` before re-throwing `err` to trigger caller transactional rollback. Furthermore, restrict `updates` to a strict whitelist of permissible configuration properties (`libraryPaths`, `folderAliases`, `telemetryEnabled`, `titleDisplayMode`, `displayProductCodes`, `preferredLocale`, `maxDepth`, `autoLaunch`, `minimizeToTray`, `exposeBetaOptions`), rejecting or stripping unexpected top-level fields outside this complete `LibraryConfig` set to prevent arbitrary property pollution on `db.config`. Persist sanitized `folderAliases` and validate incoming `libraryPaths` reordering.

In `src/main/ipc/controllers/library.controller.ts`, delegate the `'update-library-config'` IPC handler to `libraryState.updateLibraryConfig(updates)` with property whitelisting, invoking `await TelemetryShipper.getInstance().setTelemetryEnabled(updates.telemetryEnabled)` when `telemetryEnabled` is present in `updates`.

Author comprehensive Vitest unit tests in `src/main/library-state/config.test.ts` and `src/main/ipc/controllers/library.controller.test.ts`.
