# 05.2 — Extract ProcessRunner Seam into YumeEngine

## Epic
PRD 01: YumeEngine Core Architecture & Headless Extraction

## What to build
Establish the abstract `IProcessRunner` seam in `@yumeshelf/engine` for external CLI-based converters with bounded buffer limits, process escalation, and mock test fixtures.

## Blocked by
- 05.1 — Extract Headless Save Codecs into YumeEngine

## Status
done

## Acceptance criteria
- [x] Define formal `IProcessRunner` interface in `@yumeshelf/engine`:
  ```typescript
  export interface IProcessRunner {
    run(command: string, args: string[], options?: { cwd?: string; timeout?: number; env?: Record<string, string> }): Promise<{ exitCode: number; stdout: string; stderr: string }>;
  }
  ```
  Enforce default 30,000ms timeout, 2-stage shutdown escalation (SIGTERM $\to$ 3,000ms grace $\to$ SIGKILL), and $\le 10\text{MB}$ stdout/stderr buffer accumulation limit throwing typed `SaveCodecError` on overflow. Explicitly mandate that concrete Node.js process runner implementations MUST invoke external binaries using `child_process.execFile` or `child_process.spawn` with `shell: false` and direct array arguments (`args: string[]`), strictly forbidding shell wrapper invocations (`child_process.exec`, `sh -c`, `cmd.exe /c`) to prevent command injection vectors.
- [x] Implement `MockProcessRunner` fixture in `packages/yume-engine/tests/` to verify external CLI-based save converters without requiring real Python or .NET CLI dependencies in CI.
- [x] Comprehensive unit tests verifying process timeout escalation, stdout/stderr buffer clamping, and exit code handling using `MockProcessRunner`.
- [x] Execute automated unit tests via `pnpm --filter @yumeshelf/engine test -- tests/process-runner.test.ts`.
