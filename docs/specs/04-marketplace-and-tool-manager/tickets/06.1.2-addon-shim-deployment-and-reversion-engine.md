# 06.1.2 — Add-on Shim Deployment & Reversion Engine

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The `AddonLifecycleService` managing pre-launch file backups, transactional shim file mirroring from `userData/addons/<id>/` into game directories, `.yumeshelf-session.json` lockfile tracking with preliminary `'deploying'` state, and post-exit reversion with reverse depth-first directory cleanup, integrated into `PlaytimeSessionManager` via `SessionLifecycleHook`.

## Explicit Assumptions & Boundaries
- All deployed shim files are backed up and fully restored to their vanilla state on game exit or crash.
- Unlinking created directories in reverse depth-first order must catch and ignore `ENOTEMPTY` / `EEXIST` to preserve runtime mod logs and caches without aborting rollback.

## Acceptance criteria
- [ ] Implement `AddonLifecycleService` under `src/main/addons/addon-lifecycle.service.ts`, supporting optional `paths?: { addonsDir?: string }` in constructor for headless testing.
- [ ] Implement `deployShims(gameDir, enabledAddons)`:
  - Boundary Validation: Validate that all source files resolve strictly within `userData/addons/<id>/` and all target copy destinations resolve strictly within `gameDir` (`resolved === gameDir || resolved.startsWith(gameDir + path.sep)`).
  - Collision Validation: Validate that multiple enabled add-ons do not declare conflicting destination files; throw typed `ShimCollisionError` on overlap.
  - File Backup: For any destination file that already exists in the game directory, check if `<filename>.yumeshelf-bak` already exists on disk. If detected, invoke crash recovery or throw typed `StaleBackupConflictError` to prevent overwriting the vanilla binary; otherwise, create a backup copy at `<filename>.yumeshelf-bak`.
  - Session Lock Creation (Preliminary): Write `.yumeshelf-session.json` with status `'deploying'` containing POSIX-normalized relative paths of planned destination files, backup locations, and planned created directories *before* copying any files into the game root.
  - Mirror Deployment: Copy active shim files from `userData/addons/<id>/` 1:1 into the game directory.
  - Session Lock Finalization: Atomically update status in `.yumeshelf-session.json` to `'active'` upon successful completion of file copying.
- [ ] Implement `revertShims(gameDir)`:
  - Read `.yumeshelf-session.json`.
  - Validate all recorded shim paths, backup paths, and directory paths resolve strictly within `gameDir` (`resolved === gameDir || resolved.startsWith(gameDir + path.sep)`).
  - Delete all deployed shim files.
  - Restore all original files from `.yumeshelf-bak` backups atomically.
  - Unlink all recorded created directories in **reverse depth-first order** using non-recursive `fs.promises.rmdir`, catching and ignoring `ENOTEMPTY` / `EEXIST` error codes so user mod runtime logs/caches are preserved.
  - Delete `.yumeshelf-session.json`.
- [ ] Register `AddonLifecycleService` lifecycle hooks into `PlaytimeSessionManager` via `registerSessionLifecycleHook`.
- [ ] Unit & integration tests verifying clean deployment, `'deploying'` -> `'active'` status transition, collision detection, file backup/restore fidelity, reverse depth-first directory cleanup with `ENOTEMPTY` non-abort handling, and session lock cleanup.
- [ ] Execute automated tests via `npm run test:node -- tests/addon-lifecycle.test.js`.
