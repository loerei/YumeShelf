# 01.1.2.2 — Virtual Tree IPC Infrastructure, Facade Methods, and Controller Handlers

## Epic
PRD 03: Virtual Nested Folders (App Folders) & Dual Workspace Views ("Favorite Desk" vs "Library")

## What to build
Establish the Electron IPC membrane, preload bindings, and `libraryState` facade methods for virtual folder operations, favorite order synchronization, and workspace migration. Implement strict boundary schema sanitization, prototype pollution protection, and atomic write coordinator delegation.

## Acceptance criteria

- [ ] Declare IPC method types and response payloads (`get-virtual-tree`, `save-virtual-tree`, `save-favorite-order`, `migrate-virtual-workspace`) in `src/shared/types/ipc.d.ts`.
- [ ] Expose `getVirtualTree`, `saveVirtualTree`, `saveFavoriteOrder`, and `migrateVirtualWorkspace` facade methods on `libraryState` in `src/main/library-state/index.ts`, delegating to `AtomicWriteCoordinator`. Inside `libraryState.getVirtualTree()`, await `coordinator.getLatestDB()` to guarantee read-after-write consistency and avoid cold-start races.
- [ ] Implement prototype pollution sanitization helper rejecting `__proto__`, `constructor`, and `prototype` on `save-virtual-tree` deserialization, and enforce cumulative ceiling `maxTotalNodes: 10000` across virtual tree and favorites.
- [ ] On `save-virtual-tree` IPC ingress, wire `validateTreeInvariants(tree)` (`03.1.1`) directly into handler validation in `src/main/ipc/controllers/library.controller.ts`, validating recursive node schema and types (`'folder'` vs `'game'`), structural invariants (`isRootNode`, `!detectCycle`, `assertDepthWithinBounds(tree, 16)`, `assertUniqueFolderIds`, `assertUniqueGameKeys`, `assertNoPrototypePollution`); return `{ ok: false, error: 'invalid-tree-invariants' }` if validation fails.
- [ ] On `migrate-virtual-workspace` IPC ingress in `src/main/ipc/controllers/library.controller.ts`: validate `isPlainObject(payload) && isPlainObject(payload.tree) && Array.isArray(payload.favoriteOrder) && payload.favoriteOrder.every(k => typeof k === 'string' && k.trim().length > 0 && k.length <= 500 && !k.includes('\0'))`. Reject prototype keys on `payload` and `payload.configUpdates` via `assertNoPrototypePollution`. If validation fails, return `{ ok: false, error: 'invalid-migration-payload' }`. Treat `payload.configUpdates` as a partial patch: extract only explicitly declared workspace properties (`legacyMode?: boolean`, `activeWorkspaceMode?: 'favorites' | 'library'`), validate their types/enums, reject all undeclared or privileged keys (prohibiting/stripping `libraryPaths` and `libraryPath`), and merge the extracted updates onto `latestDb.config` via `latestDb.config = normalizeLibraryConfigShape({ ...latestDb.config, ...extractedUpdates })`. Symmetrically resolve and validate `payload.favoriteOrder` (resolving candidate keys via `buildLogicalGames` or physical lookup to canonical `primaryInstance.gameKey`, rejecting prototype keys, array length <= 10000, string length <= 500 chars, pruning un-favorited keys, and deduplicating entries). Execute inside a single `coordinator.mutate` transaction: reconcile root child order deterministically by validating `payload.tree` via `validateTreeInvariants(payload.tree)`, reordering existing root child items in `latestDb.virtualTree.children` to match the sequence declared in `payload.tree.children` (appending any newly discovered games not present in `payload.tree` to the end of root children), assigning `latestDb.favoriteOrder = payload.favoriteOrder`, and assigning `latestDb.config = normalizeLibraryConfigShape({ ...latestDb.config, ...extractedUpdates })`. If validation fails, roll back without persisting.
- [ ] On `save-favorite-order` IPC ingress in `src/main/ipc/controllers/library.controller.ts`: validate `Array.isArray(order) && order.every(k => typeof k === 'string' && k.trim().length > 0 && k.length <= 500 && !k.includes('\0'))`. Enforce prototype rejection (`__proto__`, `constructor`, `prototype`), resolve candidate keys via `buildLogicalGames` to canonical `primaryInstance.gameKey` before validating against `latestDb.games` strictly using `Object.hasOwn(latestDb.games, key) && Boolean(latestDb.games[key]?.favorite) === true` (pruning un-favorited keys). Enforce string length bounds (<= 500 chars) and array length bounds (<= 10000 items); deduplicate entries and return `{ ok: false, error: 'invalid-favorite-order-payload' }` on failure without throwing.
- [ ] In `src/main/library-state/actions.ts:toggleFavorite`: retain `throw new Error(`Game not found: ${gameKey}`)` for missing records (preserving existing unit test assertions in `actions-favorite.test.ts`), while the IPC handler in `src/main/ipc/controllers/library.controller.ts` validates incoming arguments (`if (typeof gameKey !== 'string' || !gameKey.trim() || gameKey.length > 500 || gameKey.includes('\0') || gameKey === '__proto__' || gameKey === 'constructor' || gameKey === 'prototype') throw new Error('invalid-game-key');`) and maps unresolvable records to `throw new Error('game-not-found')`. Defensively initialize `latestDb.favoriteOrder = Array.isArray(latestDb.favoriteOrder) ? latestDb.favoriteOrder : [];` prior to array operations, resolve the enclosing logical game group via `buildLogicalGames(normalizedGames)` (matching by physical `instance.gameKey` or logical `game.id` / continuity signature), and synchronize `favorite = nextFavorite` across ALL physical instances in `latestDb.games` belonging to that logical game group (`targetGroup.instances.forEach(i => { if (latestDb.games[i.gameKey]) latestDb.games[i.gameKey].favorite = nextFavorite; })`).
- [ ] Register IPC handlers in `src/main/ipc/controllers/library.controller.ts` connecting channels (`get-virtual-tree`, `save-virtual-tree`, `save-favorite-order`, `migrate-virtual-workspace`) to facade methods and `AtomicWriteCoordinator` (`01.1.1.1`, `01.1.1.2`), with `save-virtual-tree`, `save-favorite-order`, and `migrate-virtual-workspace` returning `Promise<{ ok: boolean; error?: string }>`. On `update-library-config` IPC ingress, validate `isPlainObject(updates)`, reject prototype pollution keys (`__proto__`, `constructor`, `prototype`) via `assertNoPrototypePollution(updates)`, prohibit and strip privileged path settings (`libraryPaths`, `libraryPath`) across BOTH defensive layers (in `library.controller.ts` on IPC ingress AND in `src/main/library-state/config.ts:updateLibraryConfig` prior to merging updates) before delegating to configuration updates, while permitting all valid non-privileged `LibraryConfig` properties (including workspace flags `activeWorkspaceMode`, `legacyMode`, and preferences `titleDisplayMode`, `displayProductCodes`, `minimizeToTray`, `exposeBetaOptions`, `telemetryEnabled`).
- [ ] Bridge IPC channels in `src/preload.ts` exposing `electronAPI.getVirtualTree`, `saveVirtualTree`, `saveFavoriteOrder`, and `migrateVirtualWorkspace`.
- [ ] Symmetrically synchronize `db.favoriteOrder` in `src/main/library-state/actions.ts:toggleFavorite`: on favorite (`nextFavorite === true`), resolve the canonical primary physical key (`primaryKey = targetGroup.primaryInstance?.gameKey || targetGroup.instances[0].gameKey`) and append to `latestDb.favoriteOrder` without duplicate entries; on un-favorite (`nextFavorite === false`), filter out all instance keys in `targetGroup.instances.map(i => i.gameKey)` from `latestDb.favoriteOrder`. Commit mutations atomically via `AtomicWriteCoordinator.mutate`.
- [ ] Author automated unit tests in `tests/virtual-tree-persistence.test.js` covering schema initialization with `schemaVersion: 2`, legacy key filtering with `KNOWN_TOP_LEVEL_SCHEMA_KEYS`, prototype pollution defense (including on `update-library-config`), structural invariant validation, favorite order array/length validation, default `legacyMode: true`, round-trip persistence, and symmetrical `toggleFavorite` synchronization.
- [ ] Execute automated unit tests via `npm run test:single -- tests/virtual-tree-persistence.test.js` with standard output containing `'✔ virtual-tree IPC persistence'` and `'ℹ pass 10'` with exit code 0.
