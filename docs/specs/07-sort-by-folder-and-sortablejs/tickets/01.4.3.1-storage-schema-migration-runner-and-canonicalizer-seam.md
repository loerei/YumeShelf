### 1. Schema Version Register & Isolated Storage Migration Runner (`src/main/library-state/migrations.ts`)
- Explicit Version Register:
  - Declare `export const CURRENT_SCHEMA_VERSION = 1;`.
  - Extend the root database envelope `LibraryDatabase` and declare `StoredGameRecord`:
    ```typescript
    export interface StoredGameRecord {
      folderPath: string;
      exePath: string;
      name?: string;
      customName?: boolean;
      folderName?: string;
      gameKey?: string;
      relativePath?: string;
      favorite?: boolean;
      playtime?: number;
      lastPlayed?: number;
      runInBackground?: boolean;
      autoTranslate?: boolean;
      dateAdded?: number;
      engine?: string | null;
      saveFolderOverride?: string;
      manual?: boolean;
      platform?: 'macos' | 'windows' | 'linux';
      sizeBytes?: number;
      sizeMtime?: number;
      [key: string]: any;
    }

    export interface LibraryDatabase {
      schemaVersion: number;
      config: LibraryConfig;
      games: Record<string, StoredGameRecord>;
      titleResolutionConfig?: {
        titleDisplayMode?: string;
        displayProductCodes?: boolean;
        preferredLocale?: string;
      };
      [key: string]: any;
    }
    ```
  - For unversioned legacy stores (missing `schemaVersion`), default `schemaVersion` to `0`.
- Sequential Migration Runner:
  - Export `runStorageMigrations(db: any, context: LibraryContext, targetPlatform?: PlatformInput): Promise<LibraryDatabase>`.
  - Migrations execute linearly ($M_{0 \to 1} \to \dots$) through an isolated runner loop wrapped with structured diagnostics:
    ```typescript
    let currentVersion = db.schemaVersion ?? 0;
    while (currentVersion < CURRENT_SCHEMA_VERSION) {
      const nextVersion = currentVersion + 1;
      const migrationFn = MIGRATIONS[nextVersion];
      if (!migrationFn || typeof migrationFn !== 'function') {
        console.error('[STORAGE_MIGRATIONS] Missing migration function for schema version:', {
          currentVersion,
          nextVersion,
          targetVersion: CURRENT_SCHEMA_VERSION
        });
        throw new Error(`Missing migration step for schema version ${nextVersion}`);
      }
      try {
        db = await migrationFn(db, context, targetPlatform);
      } catch (err) {
        console.error('[STORAGE_MIGRATIONS] Migration step execution failed:', { fromVersion: currentVersion, targetVersion: nextVersion, error: err });
        throw err;
      }
      db.schemaVersion = nextVersion;
      currentVersion = nextVersion;
    }
    return db;
    ```
- Standalone Storage Canonicalizer Helper (`canonicalizeStoredGames`):
  - Export standalone helper:
    ```typescript
    export interface CanonicalizeOptions {
      isBootstrapMigration?: boolean;
      purgeOrphans?: boolean;
    }

    export async function canonicalizeStoredGames(
      db: LibraryDatabase,
      categoryState: any,
      libraryPaths: string[],
      targetPlatform?: PlatformInput,
      options?: CanonicalizeOptions
    ): Promise<{ migratedCount: number }>;
    ```
  - Resolves canonical roots across configured paths via `subsumeLibraryPaths(libraryPaths, targetPlatform)`.
  - Batch category queries: loads `catState = await categoryState?.loadCategoryState?.()` once before iterating games. In bootstrap migration context ($M_{0 \to 1}$, `options?.isBootstrapMigration === true`), any rejection or failure during category loading must throw/rethrow out of `canonicalizeStoredGames` and `runStorageMigrations`, ensuring `loadDB()` trips `isDegradedState = true`, aborts atomic persistence of `games.json`, and does not advance `db.schemaVersion` to 1, allowing the migration to retry cleanly on the next application bootstrap without state desynchronization. In non-bootstrap runtime path mutations (`addLibraryPath`, `removeLibraryPath`, `changeLibraryPath`, `setupLibrary`), category load failures are caught, log structured diagnostic warning `console.warn('[STORAGE_CANONICALIZE] Category state load failed during runtime path mutation:', { error: err })`, allowing path mutation and database commit to proceed without tripping degraded state.
  - Iterates all entries `[legacyKey, record]` in `Object.entries(db.games || {})`:
    - Defensively validates record shape: if `!record || typeof record !== 'object' || typeof record.folderPath !== 'string' || !record.folderPath.trim()`, skip record.
    - Guards against prototype pollution: if `legacyKey === '__proto__' || legacyKey === 'constructor' || legacyKey === 'prototype'`, skip record.
    - Validates path containment via `isSubsumedBy(record.folderPath, root, targetPlatform)` against subsumed roots.
    - To eliminate un-indexed $O(K \times N)$ quadratic scans during orphan category purging, the runner MUST pre-index all surviving contained game records in `db.games` into a `Set<string>` of logical game IDs (`const survivingLogicalIds = new Set<string>(); for (const g of Object.values(db.games)) { if (isContained(g)) survivingLogicalIds.add(buildLogicalGameId(g)); }`) prior to the orphan purging sweep.
    - If uncontained: when `options?.purgeOrphans === true`, explicitly purges `delete db.games[legacyKey]`, derives `orphanId = buildLogicalGameId({ ...record, gameKey: legacyKey, relativePath: legacyKey })`, and marks `mutated = true`. Category assignments for `orphanId` (`delete catState?.assignments?.[orphanId]`) MUST only be purged if `!survivingLogicalIds.has(orphanId)`, performing an $O(1)$ set lookup to preserve category tags for surviving multi-instance game copies on remaining library paths without inner linear scans over `db.games`. Otherwise skips uncontained records.
    - If contained, derives canonical `canonicalGameKey = buildGameKey(owningLibPath, record.folderPath)`.
    - Guards derived key against prototype pollution: if `canonicalGameKey === '__proto__' || canonicalGameKey === 'constructor' || canonicalGameKey === 'prototype'`, skip record.
    - If `canonicalGameKey !== legacyKey`:
      - Checks whether `db.games[canonicalGameKey]` already exists. If present, merges state non-destructively:
        ```typescript
        const existing = db.games[canonicalGameKey];
        if (existing) {
          db.games[canonicalGameKey] = {
            ...existing,
            ...record,
            gameKey: canonicalGameKey,
            relativePath: canonicalGameKey,
            favorite: !!(existing.favorite || record.favorite),
            manual: !!(existing.manual || record.manual),
            autoTranslate: !!(existing.autoTranslate || record.autoTranslate),
            runInBackground: !!(existing.runInBackground || record.runInBackground),
            engine: existing.engine || record.engine || null,
            platform: existing.platform || record.platform,
            exePath: existing.manual ? existing.exePath : (record.manual ? record.exePath : (existing.exePath || record.exePath)),
            folderPath: existing.folderPath || record.folderPath,
            folderName: existing.folderName || record.folderName,
            sizeBytes: typeof existing.sizeBytes === 'number' ? existing.sizeBytes : record.sizeBytes,
            sizeMtime: typeof existing.sizeMtime === 'number' ? existing.sizeMtime : record.sizeMtime,
            playtime: Math.max(existing.playtime || 0, record.playtime || 0),
            lastPlayed: Math.max(existing.lastPlayed || 0, record.lastPlayed || 0),
            name: existing.customName ? existing.name : (record.customName ? record.name : (existing.name || record.name)),
            customName: !!(existing.customName || record.customName),
            saveFolderOverride: existing.saveFolderOverride || record.saveFolderOverride,
            dateAdded: Math.min(existing.dateAdded || Date.now(), record.dateAdded || Date.now())
          };
        } else {
          db.games[canonicalGameKey] = {
            ...record,
            gameKey: canonicalGameKey,
            relativePath: canonicalGameKey
          };
        }
        if (Object.prototype.hasOwnProperty.call(db.games, legacyKey)) {
          delete db.games[legacyKey];
        }
        delete db.games[canonicalGameKey]?.migratedFromGameKey;
        ```
      - Re-maps category assignments: derives `newGameId = buildLogicalGameId(db.games[canonicalGameKey])` and `fallbackOldId = buildLogicalGameId({ ...record, gameKey: legacyKey, relativePath: legacyKey })`.
      - If `categoryState` is provided and `newGameId !== fallbackOldId`:
        - Wrapped in an isolated `try ... catch` error boundary with structured diagnostic logging (`console.error('[STORAGE_CANONICALIZE] Failed to migrate category assignments:', { newGameId, fallbackOldId, error: err })`):
          - Evaluates `if (catState?.assignments && Array.isArray(catState.assignments[fallbackOldId]) && catState.assignments[fallbackOldId].length > 0)`.
          - Merges in-memory: `const merged = Array.from(new Set([...(catState.assignments[newGameId] || []), ...catState.assignments[fallbackOldId]]))`, assigns `catState.assignments[newGameId] = merged;`, deletes `catState.assignments[fallbackOldId];`, and marks `mutated = true;`.
  - Sweeps all records in `db.games` to purge transient migration metadata across canonical records:
    ```typescript
    for (const record of Object.values(db.games)) {
      if (record && typeof record === 'object') {
        delete (record as any).migratedFromGameKey;
      }
    }
    ```
  - If batched `catState` was mutated, commits changes strictly ONCE via a single atomic write `await categoryState.saveCategoryState(catState)` upon loop completion. In bootstrap migration context ($M_{0 \to 1}$, `options?.isBootstrapMigration === true`), any rejection or failure during category saving must throw/rethrow out of `canonicalizeStoredGames` and `runStorageMigrations`, ensuring `loadDB()` trips `isDegradedState = true`, aborts atomic persistence of `games.json`, and does not advance `db.schemaVersion` to 1, allowing the migration to retry cleanly on the next application bootstrap without category state corruption. In non-bootstrap runtime path mutations (`addLibraryPath`, `removeLibraryPath`, `changeLibraryPath`, `setupLibrary`), category save failures are caught, log structured diagnostic warning `console.warn('[STORAGE_CANONICALIZE] Category state migration failed during runtime path mutation:', { error: err, migratedCount })`, and allow path mutation and database commit to proceed without tripping degraded state.
- Monotonic Migration $M_{0 \to 1}$ (Path Subsumption Key Canonicalization & Category Continuity):
  - Normalizes root database envelope:
    1. Initializes `db.games = (db.games && typeof db.games === 'object') ? db.games : {};`.
    2. Scans root `db` envelope for unversioned top-level legacy game records, verifying `Object.prototype.hasOwnProperty.call(db, key)` and guarding against prototype pollution keys (`key !== '__proto__' && key !== 'constructor' && key !== 'prototype' && key !== 'config' && key !== 'games' && key !== 'schemaVersion' && key !== 'titleResolutionConfig' && typeof val === 'object' && val && typeof val.folderPath === 'string' && val.folderPath.trim().length > 0 && typeof val.exePath === 'string' && val.exePath.trim().length > 0`).
    3. For each detected legacy record, resolves `effectiveFolder`:
       - If `record.folderPath` or `record.exePath` resides in a macOS `.app` bundle, resolves to the bundle root via `resolveBundleRoot(record.exePath)` (or `folderPath.endsWith('.app')`) and sets `effectiveFolder` to the `.app` bundle root.
       - If `path.dirname(record.exePath)` is a descendant of `record.folderPath` (via `isDescendantPath(record.folderPath, path.dirname(record.exePath))` or segment containment), iteratively unwraps wrapper directories in a `while` loop while `path.basename(currentDir).toLowerCase()` matches `WRAPPER_DIRECTORY_NAMES` (imported from `./scanner`: `'app', 'bin', 'binaries', 'data', 'game', 'release', 'runtime', 'win64', 'windows', 'x64', 'x86', 'linux', 'linux64', 'x86_64'`), terminating when a non-wrapper directory is reached or when `currentDir` reaches `record.folderPath`. Only if `currentDir` remains a genuine non-wrapper subdirectory of `record.folderPath` (e.g. version folders), resolves `effectiveFolder = currentDir`. Otherwise, retains `effectiveFolder = record.folderPath`.
       Updates `record.folderPath = effectiveFolder` and `record.folderName = getFolderBaseName(effectiveFolder) || record.folderName || getLeafFolderName(effectiveFolder)`. Adopts the record into `db.games[key] = { ...record, folderPath: effectiveFolder, folderName: record.folderName, gameKey: key, relativePath: key }` under its original uncanonicalized legacy `key` (if not already present under that key) before deleting root property `delete db[key]`. By adopting top-level records under their uncanonicalized legacy key, subsequent execution of `canonicalizeStoredGames` detects `canonicalGameKey !== legacyKey`, seamlessly migrating the record to `db.games[canonicalGameKey]` and remapping historical category assignments in `categoryState.assignments`.
    4. Normalizes `db.config` via `normalizeLibraryConfigShape(db.config, targetPlatform)`. If `normalizedConfig.libraryPaths` is empty and `context.fsSync?.existsSync(context.defaultGamesDir)` is true, populates `normalizedConfig.libraryPaths = [context.defaultGamesDir]` (strictly mirroring `src/main/library-state/config.ts:10`). Commits `db.config = normalizedConfig;`.
  - Delegates storage and category re-keying to `await canonicalizeStoredGames(db, context.categoryState, db.config.libraryPaths, targetPlatform, { isBootstrapMigration: true })` and returns the transformed `db` to the runner loop. The runner loop in `runStorageMigrations` stamps `db.schemaVersion = nextVersion;`, and the storage bootstrap coordinator in `createLibraryState.loadDB()` performs the single atomic disk commit via `await persistDbDirectly(data)` upon resolution of `runStorageMigrations`.

### 2. Storage Lifecycle Isolation at Bootstrap (`src/main/library-state/index.ts`)
- In `createLibraryState(options: LibraryContext)`:
  - In `loadDB()`:
    - Uniformly wraps database retrieval whether provided via injected `(options as any).loadDB` or default file reader `readJsonWithRetry(options.dbFilePath)`.
    - If `options.fs.stat` or `readJsonWithRetry` throws `ENOENT` (fresh application install), returns canonical root database envelope pre-anchored at `CURRENT_SCHEMA_VERSION`:
      ```typescript
      if (err?.code === 'ENOENT') {
        isDegradedState = false;
        return {
          schemaVersion: CURRENT_SCHEMA_VERSION,
          config: normalizeLibraryConfigShape({}, targetPlatform),
          games: {}
        };
      }
      ```
    - Whenever `isDegradedState` is set to `true` due to a zero-byte file (`stats?.size === 0`) or a non-`ENOENT` file read failure (`readJsonWithRetry` throwing e.g. JSON `SyntaxError`, `EACCES`, `EPERM`, `EIO`), emit structured diagnostic error logging capturing the file path, failure reason, and underlying error stack:
      `console.error('[LIBRARY_STATE] Storage load failed, entering degraded state:', { dbFilePath: options.dbFilePath, reason: stats?.size === 0 ? 'zero-byte-file' : 'read-error', error: err });`
      before returning `cachedDb || {}`.
    - If database is not in degraded state (`!isDegradedState && data && typeof data === 'object'`):
      - Checks `const initialVersion = data.schemaVersion ?? 0;`.
      - If `initialVersion < CURRENT_SCHEMA_VERSION`:
        - Dispatches migration task into `serializedQueue` with double-checked locking: inside the queued task, checks `if (isDegradedState || (cachedDb && (cachedDb.schemaVersion ?? 0) >= CURRENT_SCHEMA_VERSION)) return cachedDb || data;`. If a queued migration task executes after a preceding task has tripped `isDegradedState = true`, the queued task must immediately abort migration execution without attempting secondary migrations. If still unmigrated, wraps migration and persistence in a `try ... catch` block: executes `data = await runStorageMigrations(data, context, options.targetPlatform);`, atomically persists migrated database to disk via `await persistDbDirectly(data);`, updates `cachedDb = data;`, and returns `data`. On rejection, logs structured diagnostics (`console.error('[STORAGE_MIGRATIONS] Migration runner failed, entering degraded state:', { initialVersion, targetVersion: CURRENT_SCHEMA_VERSION, error: err })`), sets `isDegradedState = true`, and returns `cachedDb || data` (or throws) to authoritatively trip the application circuit breaker.
    - Returns authoritative canonical database with `schemaVersion: 1`.
  - Guarantees migrations execute exclusively during storage initialization at application bootstrap, before domain services, scanners/loaders, IPC controllers, or UI components mount.
  - Satisfies atomic file replacement via `writeAtomicJson`.
