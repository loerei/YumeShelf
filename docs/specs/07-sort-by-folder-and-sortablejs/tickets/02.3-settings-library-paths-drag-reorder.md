# 02.3 — Settings Library Paths Drag-and-Drop Controller & Settings Integration ($B$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Implement `src/renderer/settings/path-dnd.ts` to manage vertical SortableJS drag-and-drop reordering for configured library paths inside Settings (`#library-paths-container`):
1. Attach SortableJS with `handle: '.grip-handle'`, `animation: options.animationDuration ?? 180`, `forceFallback: true`, `fallbackClass: 'sortable-row-fallback'`, `fallbackTolerance: options.fallbackTolerance ?? 5`, and accept optional `sortableFactory?: { create: (element: HTMLElement, options?: any) => any; get?: (element: HTMLElement) => any; }` (defaulting to native `Sortable`) in `PathDndOptions` for headless Vitest testability without JSDOM. The path drag fallback element (`.sortable-row-fallback`) must declare an elevated tokenized elevation level (`z-index: var(--zIndex-path-row-drag, 2100)`, defined in `src/styles/theme.css`) positioned above the settings modal panel and overlay (stacking level 2000) and beneath toast notifications (stacking level 10005), ensuring dragged rows remain fully visible when appended to the document root during modal interactions.
2. Guard Sortable creation by destroying any pre-existing instance (`(options.sortableFactory ?? Sortable).get(container)?.destroy()`) before instantiating `(options.sortableFactory ?? Sortable).create(container)`.
3. Expose explicit lifecycle and test seams: `destroy(): void` invoking `sortable?.destroy()`, and `handlePathDragEnd: (evt: any) => Promise<void> | void` exposing the SortableJS `onEnd` handler forwarding the promise returned by `onOrderChanged(newPaths)` for headless unit testing.
4. Implement boundary auto-scroll when dragging near container edges.
5. In SortableJS `onEnd`, extract reordered paths by reading `el.dataset.path` from container child elements (`.library-path-entry`), include an identity order guard (`if (evt.oldIndex === evt.newIndex) return;`), and trigger `onOrderChanged(newPaths)` on drop, returning the promise from `handlePathDragEnd`. The emitted `newPaths` array represents a reordered permutation of configured paths, passed directly to `updateLibraryConfig` (matching `PRD.md:804`) to preserve explicit user-defined ordering across both ancestor and descendant paths, validated by the `updateLibraryConfig` permutation defense (Ticket `01.4.1.2.1`).

Update `src/renderer/settings.ts`:
1. Extend `SettingsControllerOptions` interface to declare `electronAPI?: any;`, `getLibraryConfig?: () => any;`, `pathDndOptions?: PathDndOptions;` (accepting `sortableFactory?: { create: (element: HTMLElement, options?: any) => any; get?: (element: HTMLElement) => any; }`), `targetPlatform?: PlatformInput;`, `showToastPill?: (text: string) => void;`, `i18n?: (key: string) => string;`, and `onConfigUpdated?: (config: any) => void;`. Prohibit calling ambient global `(window as any).electronAPI`. Route all configuration updates and path actions (`addLibraryPath`, `changeLibraryPath`, `removeLibraryPath`) through injected `options.electronAPI`.
2. In `renderLibraryPaths`, track `currentLibraryPaths: string[]` and `currentFolderAliases?: Record<string, string>` in controller state. Mount grip handles (`.grip-handle`) on each row rendering an inline vector SVG grip icon (such as a 6-dot matrix glyph) equipped with localized accessible name (`options.i18n?.('reorder_library_path') ?? 'Reorder library path'`) on `aria-label` and localized visual tooltip attribute (`data-tooltip` backed by `options.i18n?.('drag_to_reorder') ?? 'Drag to reorder'`), attach canonical path dataset attribute `entry.dataset.path = p` directly to each `.library-path-entry` element, and render entries safely using `textContent` or `escapeHtml`. Display folder alias (resolving via own-property check `(folderAliases && Object.prototype.hasOwnProperty.call(folderAliases, normalizePathForPlatform(p, options.targetPlatform)) && folderAliases[normalizePathForPlatform(p, options.targetPlatform)]?.trim()) ? folderAliases[normalizePathForPlatform(p, options.targetPlatform)].trim() : getFolderBaseName(p)`) alongside canonical path. Update `applyLibraryConfig(config)` to pass `config.folderAliases` into `renderLibraryPaths(config.libraryPaths, config.folderAliases)`.
3. Attach `path-dnd.ts` controller forwarding `options.pathDndOptions`. Ensure pre-destruction of previous Sortable instances. In `onOrderChanged(newPaths)`, disable container pointer interaction during in-flight IPC persistence and wrap in `try ... catch ... finally`:
   ```typescript
   container.style.pointerEvents = 'none';
   try {
     const currentConfig = options.getLibraryConfig?.() || options.currentConfig;
     const nextConfig = await options.electronAPI.updateLibraryConfig({ libraryPaths: newPaths });
     if (nextConfig) {
       options.onConfigUpdated?.(nextConfig);
     } else {
       throw new Error('updateLibraryConfig returned falsy');
     }
   } catch (err) {
     const currentConfig = options.getLibraryConfig?.() || options.currentConfig;
     const fallbackPaths = currentConfig?.libraryPaths || currentLibraryPaths;
     const fallbackAliases = currentConfig?.folderAliases || currentFolderAliases;
     if (fallbackPaths) {
       renderLibraryPaths(fallbackPaths, fallbackAliases);
     }
     options.showToastPill?.(options.i18n?.('toast_path_reorder_failed') ?? 'Failed to update library paths order. Reverting changes.');
     console.error('[SETTINGS] Failed to persist reordered library paths, rolled back:', { newPaths, error: err });
   } finally {
     container.style.pointerEvents = '';
   }
   ```
   to persist reordered paths and forward normalized `LibraryConfig`, restoring DOM rows while preserving keyboard focus on failure without post-render DOM re-querying hacks and maintaining contract symmetry with `shelf-tabs.ts`.
4. Enforce max 4 visible rows (~180px) before vertical scrolling, mandating stable scrollbar space reservation (`scrollbar-gutter: stable`) on `.library-paths-list` (`#library-paths-container`) to eliminate horizontal layout shift when vertical overflow toggles.

Update `src/renderer/bootstrap/app-composition.ts`:
1. Declare `pathDndOptions?: PathDndOptions` on `RendererCompositionOptions` interface and destructure it in `createRendererComposition`.
2. In `createRendererComposition`, wire dependencies into `createSettingsController`:
   - `electronAPI`
   - `getLibraryConfig: () => state.getCurrentLibraryConfig()`
   - `pathDndOptions: options.pathDndOptions`
   - `onConfigUpdated: (nextConfig) => { state.setCurrentLibraryConfig(nextConfig); libraryRuntime.sortGames(state.getCurrentSort()); }`

Provide comprehensive Vitest unit tests in `src/renderer/settings/path-dnd.test.ts`.
