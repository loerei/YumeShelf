# 05.1.1.1 — Game Add-on State Persistence & Migration (Preparatory Seam $S$)

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
The per-game tool state persistence data model in `games.json` (`libraryState`), schema normalization default (`addons: []`), legacy `autoTranslate` backward compatibility migration with ghost property deletion, atomic write-and-replace persistence, and main IPC contracts (`addon:get-game-addons`, `addon:set-game-addon-enabled`, `addon:update-game-addon-config`) exposed on `window.electronAPI`.

## Explicit Assumptions & Boundaries
- Storage Separation: Non-sensitive per-game options are persisted in `game.addons[].config` inside `games.json`. Sensitive credentials MUST NEVER be stored in `games.json`.
- Establishes the decoupled backend data model seam ($S$) required by the Prism Tool Manager UI (Ticket 05.1.1.2) and Cascading Context Menu (Ticket 05.1.2).

## Acceptance criteria
- [ ] Update `normalizeGameRecord` and `buildLogicalGames` in `src/main/library-state/continuity.ts` and `src/main/library-state/loader.ts` to initialize and project `addons: Array.isArray(record.addons) ? record.addons : []` by default for all records, verifying `typeof item.id === 'string'`, `typeof item.enabled === 'boolean'`, defaulting `item.config` to `{}` if non-object, and deduplicating entries by unique `id`. Remove legacy `autoTranslate` property synthesis.
- [ ] Implement per-game tool state persistence in JSON database (`libraryState` / `games.json` under `game.addons: Array<{ id: string; enabled: boolean; config: Record<string, any> }>`). Enforce upsert semantics on `id` for `addon:set-game-addon-enabled` and `addon:update-game-addon-config`.
- [ ] Serialize all write mutations to `libraryState` through an in-memory sequential promise chain (`mutateDB(updater)`), isolating errors (`promise.catch(() => {})`) to ensure rejected transactions do not deadlock subsequent queued updates. `loadGamesForConfig()` in `loader.ts` commits library rescan updates through `mutateDB(updater)`, merging discovered file metadata (`sizeBytes`, `sizeMtime`, `engine`, `exePath`) into the latest live database state without clobbering dynamic fields (`addons`, `playtime`, `lastPlayed`, `favorite`, `customName`, `saveFolderOverride`).
- [ ] Implement legacy `autoTranslate` migration on `libraryState` initialization: if `game.autoTranslate === true` and `game.addons` does not contain `xunity-autotranslator`, automatically synthesize `{ id: 'xunity-autotranslator', enabled: true, config: {} }` into `game.addons`. Unconditionally **delete** the legacy `game.autoTranslate` property across all stored records.
- [ ] Refactor `src/main/library-state/actions.ts: toggleAutoTranslate` to delegate to toggling `{ id: 'xunity-autotranslator' }` in `game.addons` instead of mutating legacy `autoTranslate`.
- [ ] Implement atomic write-and-replace (`.tmp` -> `fsync` -> `rename`) for persisting updated game records to `games.json`.
- [ ] Implement IPC handlers for querying and updating assigned tools:
  - `addon:get-game-addons`: Return `game.addons` for a specified `gameKey`.
  - `addon:set-game-addon-enabled`: Toggle enabled state with validation.
  - `addon:update-game-addon-config`: Persist tool-specific configuration options in `game.addons[].config`.
- [ ] Expose game add-on persistence IPC channels (`addon:get-game-addons`, `addon:set-game-addon-enabled`, `addon:update-game-addon-config`) on `window.electronAPI` in `src/preload.ts` and declare typed signatures in `src/shared/types/ipc.d.ts`.
- [ ] Unit tests in `tests/game-addon-persistence.test.js` verifying schema validation, default `addons: []` normalization, legacy `autoTranslate` synthesized migration with property deletion, atomic disk write, and persistence mutation integrity.
- [ ] Execute automated unit tests via `npm run test:node -- tests/game-addon-persistence.test.js`.
