# 01.1 — Card Dataset Seams & SortableJS Dependencies ($S$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Install `sortablejs` (`^1.15.2`) in `dependencies` and `@types/sortablejs` (`^1.15.8`) in `devDependencies` within `package.json`. Extend the card factory parameter seams (`createCard(game, options)` in `src/renderer/game-cards.ts` and `createStackCard(stack, options)` in `src/renderer/stack-cards.ts`) to accept `options.rootFolderPath?: string`, and assign `card.dataset.rootFolderPath = options.rootFolderPath || ''` and `card.dataset.folderPath = game.folderPath || ''` (for single cards) and `stack.primaryGame?.folderPath || stack.folderPath || ''` (for stack cards) so downstream SortableJS drag validators can verify owning library folder boundaries without path granularity mismatch.

To guarantee non-destructive phased rollout without intermediate runtime drag regression across sequential PRs, existing HTML5 `draggable` attributes and event listeners (`ondragstart`, `ondragend`, `ondragenter`, `ondragleave`, `ondragover`, `ondrop`) and bootstrap zone attachment (`attachZoneHandlers()`) are preserved during this preparatory ticket, and will be cut over and purged in Ticket `01.3.2` once SortableJS grid binding is active.

Author unit tests in `src/renderer/game-cards.test.ts` verifying that card factories correctly populate `dataset.rootFolderPath` and `dataset.folderPath` while preserving card rendering.
