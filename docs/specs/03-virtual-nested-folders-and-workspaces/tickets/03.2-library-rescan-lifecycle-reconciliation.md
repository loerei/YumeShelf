# 03.2 — Library Rescan Lifecycle Reconciliation

## Epic
PRD 03: Virtual Nested Folders (App Folders) & Dual Workspace Views ("Favorite Desk" vs "Library")

## What to build

Integrate `VirtualTreeManager` with the Main process library scanner lifecycle (`src/main/library-state/loader.ts`) to reconcile disk rescan results against `virtualTree` and `db.favoriteOrder`, prevent cold-start race conditions with renderer migration, and cleanly prune uninstalled games without corrupting folder hierarchy.

## Acceptance criteria

- [ ] Import `VirtualTreeManager` from `../../shared/virtual-tree/manager` into `src/main/library-state/loader.ts` (`loadGamesForConfig`).
- [ ] In `loadGamesForConfig`, reconcile `virtualTree` and `db.favoriteOrder` against scanned disk results, defensively initializing default root container (`{ id: 'root', name: 'Root', type: 'folder', children: [], dateCreated: Date.now() }`) if `!latestDb.virtualTree`.
- [ ] Inspect `migratedFromGameKey` on candidate game records during rescan reconciliation: check whether `gameKey` is already present elsewhere in `virtualTree`. If `gameKey` already exists, prune the stale `migratedFromGameKey` node to preserve the `assertUniqueGameKeys` invariant; otherwise, update matching `VirtualGameRefNode.gameKey` in-place within `virtualTree` from `migratedFromGameKey` to `gameKey` and update `db.favoriteOrder` in-place, preserving existing folder placement and custom favorite ordering when games are moved on disk.
- [ ] Group candidate records using `buildLogicalGames`: append newly discovered games present on disk (`nextGames`) but absent from `virtualTree` as `VirtualGameRefNode` at root level (`virtualTree.children`) without duplicate `gameKey` references. If any physical instance of a logical game group is already present in `virtualTree`, do NOT append secondary instances to `virtualTree.children` at root.
- [ ] Logical game instance repointing before pruning: For any `VirtualGameRefNode` in `virtualTree` whose physical `gameKey` is missing from `nextGames`, inspect `previousGames[missingGameKey]` to compute its continuity signature and logical identity (`buildContinuitySignature(previousRecord)` and `buildLogicalGameId(previousRecord)`) against `buildLogicalGames(normalizedNextGames)`. If a surviving instance exists on disk in `nextGames`, check if `primaryInstance.gameKey` is already referenced elsewhere in `virtualTree`: only repoint `VirtualGameRefNode.gameKey` in-place if it is not already present; if `primaryInstance.gameKey` is already in `virtualTree`, prune the orphaned node to prevent duplicate keys. Crucially, propagate live mutable user state (specifically `favorite = true` and cumulative `playtime`) from `previousGames[missingGameKey]` to `nextGames[primaryInstance.gameKey]` so that subsequent `favoriteOrder` reconciliation retains the favorite placement. Symmetrically deduplicate `latestDb.favoriteOrder` so `primaryInstance.gameKey` appears at most once. Only prune nodes from `virtualTree` whose logical game groups have zero surviving physical instances on disk.
- [ ] Execute staged reconciliation for `db.favoriteOrder` in `loader.ts`:
  - Stage 1: Update migrated keys in-place (`migratedFromGameKey -> gameKey`) and deduplicate (`Array.from(new Set(...))`).
  - Stage 2: Repoint keys in-place to surviving instances of logical game groups with deduplication.
  - Stage 3: Only after Stages 1 and 2 complete, prune dead and un-favorited keys from `latestDb.favoriteOrder`, resolve surviving games via `buildLogicalGames(normalizedNextGames)` to extract canonical primary physical keys (`primaryInstance.gameKey`) for each logical game where `Boolean(game.favorite) === true`, append any favorited primary keys not already present in `latestDb.favoriteOrder`, followed by deduplication: `const canonicalFavoriteKeys = buildLogicalGames(normalizedNextGames).filter((game: any) => Boolean(game.favorite)).map((game: any) => game.primaryInstance.gameKey); latestDb.favoriteOrder = Array.from(new Set([...(latestDb.favoriteOrder || []).filter((key: string) => Boolean(nextGames[key]?.favorite)), ...canonicalFavoriteKeys]));`.
- [ ] Execute recursive post-order cleanup via `VirtualTreeManager.pruneEmptyFolders` to automatically dissolve folders emptied by disk deletions (preserving `root`).
- [ ] After asynchronous disk scanning and candidate statting complete in `loadGamesForConfig`, access `context.coordinator.mutate((latestDb) => { ... })` via the injected `LibraryContext` bridge to execute tree reconciliation and persistence:
  - Capture pre-rescan snapshot: `const previousGames = { ...latestDb.games };` at the beginning of the mutation transaction before updating `latestDb.games`, maintaining lexical access to pre-scan records throughout reconciliation steps.
  - Add defensive root initialization: `if (!latestDb.virtualTree) latestDb.virtualTree = { id: 'root', name: 'Root', type: 'folder', children: [], dateCreated: Date.now() };`.
  - For every record in `nextGames`, resolve surviving user records strictly using `Object.hasOwn` (rejecting prototype property keys `__proto__`, `constructor`, `prototype`, `toString`, `valueOf`, `hasOwnProperty`): `const sourceRecord = Object.hasOwn(latestDb.games, gameKey) ? latestDb.games[gameKey] : (record.migratedFromGameKey && Object.hasOwn(latestDb.games, record.migratedFromGameKey) ? latestDb.games[record.migratedFromGameKey] : undefined);` and preserve live mutable user fields: `favorite`, `playtime`, `lastPlayed`, `autoTranslate`, `runInBackground`, `saveFolderOverride`, and `customName`/`name` (when `customName === true`).
  - Explicitly assign `latestDb.games = nextGames;`.
  - Merge configuration safely preserving workspace options: `latestDb.config = normalizeLibraryConfigShape({ ...latestDb.config, ...normalizedConfig, legacyMode: latestDb.config?.legacyMode ?? normalizedConfig.legacyMode, activeWorkspaceMode: latestDb.config?.activeWorkspaceMode ?? normalizedConfig.activeWorkspaceMode })`.
  - Persist title resolution config: assign `latestDb.titleResolutionConfig = { titleDisplayMode: normalizedConfig.titleDisplayMode, displayProductCodes: normalizedConfig.displayProductCodes, preferredLocale: normalizedConfig.preferredLocale };`, preserving parity with `src/main/library-state/loader.ts:195-199` and `DatabaseSchema.titleResolutionConfig`.
  - Retain monotonic `schemaVersion` established during initialization migrations without ad-hoc runtime stamping.
  - Ensures reconciliation operates strictly on the freshest in-memory database state and commits atomically without lost updates from concurrent IPC mutations.
- [ ] Comprehensive unit tests covering scanner reconciliation: startup race bypass, new game addition to root, deleted game pruning across nested folders, symmetric favorite order pruning, empty folder post-pruning, and structure preservation.
- [ ] Execute automated rescan reconciliation tests via `npm run test:single -- tests/rescan-tree-lifecycle.test.js` with standard output containing `'✔ rescan reconciliation'` and `'ℹ pass 9'` with exit code 0.
