1. **Cold-Boot Library Initialization Hook with Configuration, Path Annotation Hydration & Deferred Update Handling (`useBootstrapLibrary.ts`)**:
   - Create [`src/renderer/hooks/useBootstrapLibrary.ts`](file:///d:/Projects/YumeShelf/src/renderer/hooks/useBootstrapLibrary.ts):
     ```typescript
     import { GameEntry, LibraryConfig } from '../types/game';
     import { CategoryNode } from '../domain/category-tree';
     import { ObservableUiRuntimeStore } from '../state/ui-runtime-state';

     export interface AppBootstrapResult {
       readonly config: LibraryConfig | null;
       readonly games: readonly GameEntry[];
       readonly categoryTree: readonly CategoryNode[];
       readonly postUpdateNotice?: {
         readonly version?: string;
         readonly fromVersion?: string;
         readonly installed?: boolean;
       } | null;
       readonly deferredAppUpdateInstall?: {
         readonly pending: boolean;
         readonly update?: unknown;
         readonly statusText?: string;
       } | null;
     }

     export type BootstrapState =
       | { readonly status: 'loading' }
       | { readonly status: 'installing-update'; readonly update?: unknown; readonly statusText?: string }
       | {
           readonly status: 'success';
           readonly data: AppBootstrapResult;
           readonly refresh: () => Promise<void>;
           readonly isRefreshing: boolean;
         }
       | { readonly status: 'error'; readonly error: Error; readonly retry: () => void };

     export function useBootstrapLibrary(
       store?: ObservableUiRuntimeStore,
       electronAPI?: ElectronAPI,
       storage?: UiStorageAdapter
     ): BootstrapState;
     ```
   - When `store` is omitted, `useBootstrapLibrary` falls back to `useContext(LibraryStoreContext)` from Ticket 03.2, removing the requirement to thread the store instance explicitly through props.
   - Defensively resolves the effective Electron API via:
     ```typescript
     const api = electronAPI ?? (typeof window !== 'undefined' ? window.electronAPI : undefined);
     ```
     If `!api` or required methods are missing, `useBootstrapLibrary` must immediately transition state to `{ status: 'error', error: new Error('Electron API is unavailable in current environment'), retry: () => void }` inside `useEffect`, rather than attempting property access on `undefined` or throwing unhandled `TypeError` exceptions in headless test environments.
   - Initializes hook state directly with `{ status: 'loading' }` on initial mount (`const [state, setState] = useState<BootstrapState>({ status: 'loading' });`), preventing `AppShell` from falling through to the empty library grid on Frame 0 before `useEffect` triggers data loading.
   - On component mount, orchestrates initial library state loading: wraps data fetching in a defensive `try ... catch` error boundary, invoking `api.bootstrapApp?.()`, falling back to `api.checkConfig()`, `api.getGames()`, and `api.getCategoryTree()`. If asynchronous bootstrap fails or throws an exception:
     1. Defensively normalizes caught rejections (`err: unknown`) and logs structured diagnostics with error and stack routed through `sanitizeUserPaths` from `src/shared/path-sanitizer.ts`:
        ```typescript
        } catch (err: unknown) {
          const rawErrorMsg = err instanceof Error ? err.message : String(err);
          const rawStack = err instanceof Error && err.stack ? err.stack : '';
          console.error('[useBootstrapLibrary] Bootstrap failed:', {
            error: sanitizeUserPaths(rawErrorMsg),
            stack: sanitizeUserPaths(rawStack)
          });
          setBootstrapState({
            status: 'error',
            error: err instanceof Error ? err : new Error(String(err)),
            retry
          });
        }
        ```
   - Manages an `isCancelled` unmount cancellation flag inside `useEffect` to prevent post-unmount state transitions and uncoordinated IPC launches.
   - **Deferred App Update Installation Lifecycle**: When `result?.deferredAppUpdateInstall?.pending` is detected:
     - Transitions state to `{ status: 'installing-update', update: result.deferredAppUpdateInstall.update, statusText: result.deferredAppUpdateInstall.statusText ?? 'Applying update package...' }`.
     - Invokes `api.beginDeferredAppUpdateInstall?.()`.
     - Enforces positive launch assertion (`if (!launchResult || launchResult.launched !== true)`): throws an error (`launchResult?.error || launchResult?.reason || 'Deferred update installer failed to launch or is unsupported on this platform.'`) and fails closed to `{ status: 'error', error, retry }` to allow user re-attempt.
   - On normal bootstrap completion:
     - Hydrates active library configuration into the store via `store.setCurrentLibraryConfig(config)` prior to or alongside `store.setCategoryTree(tree)` and `store.setAllGames(annotatedGames)`, ensuring `store.getSnapshot().currentLibraryConfig` is populated for subsequent Phase 2 `onGameStopped` re-annotations.
     - Imports `annotateGamesForDisplay` from `../game-annotations` and passes raw game records and active library configuration (`config`) through `annotateGamesForDisplay(games, config, displayMode)` to populate `locationLabel`, `parentLocationLabel`, and `relativePathDisplay` before storing them via `store.setAllGames(annotatedGames)`.
     - Imports `readStoredCustomOrder`, `writeCustomOrder`, and `migrateStoredCustomOrderAliases` from `../library-order`. Reconciles and migrates legacy custom order aliases:
       ```typescript
       // Guarded cold-boot custom order alias migration:
       // Requires BOTH storedOrder.length > 0 and annotatedGames.length > 0 to prevent purging on empty/uninitialized library
       const storedOrder = readStoredCustomOrder(storage);
       if (storedOrder.length > 0 && annotatedGames.length > 0) {
         const migratedOrder = migrateStoredCustomOrderAliases(annotatedGames, storedOrder);
         if (migratedOrder !== null) {
           writeCustomOrder(migratedOrder, storage);
         }
       }
       ```
     - Commits `{ status: 'success', data: result, refresh, isRefreshing: false }`.
   - **Declarative Library Rescan Lifecycle (`refresh()`)**:
     - Under `{ status: 'success' }`, `useBootstrapLibrary` exposes `refresh: () => Promise<void>` and `isRefreshing: boolean`, accepting an optional 4th parameter:
       ```typescript
       export function useBootstrapLibrary(
         store?: ObservableUiRuntimeStore,
         electronAPI?: ElectronAPI,
         storage?: UiStorageAdapter,
         onRefreshError?: (error: Error) => void
       ): BootstrapState;
       ```
     - Concurrency & Unmount Guard: Enforces an in-flight re-entrancy lock (`if (isRefreshingRef.current) return;`) to drop redundant calls from rapid clicks or concurrent events without dispatching duplicate IPC requests, and maintains an `isMountedRef` (`useRef(true)` with `useEffect` cleanup `isMountedRef.current = false`) checking `if (!isMountedRef.current) return;` post-await and before updating state in `catch`/`finally` to discard background rescan store mutations and prevent post-unmount React state warnings.
     - Non-Unmounting In-Flight State: During an active `refresh()`, sets `isRefreshing: true` while strictly preserving `status: 'success'`. It MUST NOT transition back to `status: 'loading'` or unmount `<Header />` or child views during background filesystem rescanning.
     - Multi-Entity Synchronization: Re-queries `api.getGames()`, `api.getCategoryTree()`, and `api.checkConfig()`, extracts `locationDisplayMode` from store snapshot, re-annotates games via `annotateGamesForDisplay(games, config, locationDisplayMode)`, and symmetrically updates `store.setCurrentLibraryConfig(config)`, `store.setCategoryTree(tree)`, and `store.setAllGames(annotatedGames)` to ensure category filters, directory trees, and library configuration remain completely synchronized with filesystem and preference changes.
       ```typescript
       const isMountedRef = useRef(true);
       useEffect(() => {
         isMountedRef.current = true;
         return () => {
           isMountedRef.current = false;
         };
       }, []);

       const refresh = useCallback(async () => {
         if (isRefreshingRef.current) return;
         isRefreshingRef.current = true;
         setIsRefreshing(true);
         try {
           const [games, tree, config] = await Promise.all([
             api.getGames(),
             api.getCategoryTree(),
             api.checkConfig(),
           ]);
           if (!isMountedRef.current) return;

           const { locationDisplayMode } = store.getSnapshot();
           const annotatedGames = annotateGamesForDisplay(games, config, locationDisplayMode);
           store.setCurrentLibraryConfig(config);
           store.setCategoryTree(tree);
           store.setAllGames(annotatedGames);
         } catch (err) {
           if (!isMountedRef.current) return;
           console.error('[useBootstrapLibrary] Refresh failed:', {
             error: sanitizeUserPaths(err instanceof Error ? err.message : String(err)),
             stack: err instanceof Error && err.stack ? sanitizeUserPaths(err.stack) : undefined,
           });
           onRefreshError?.(err instanceof Error ? err : new Error(String(err)));
         } finally {
           isRefreshingRef.current = false;
           if (isMountedRef.current) {
             setIsRefreshing(false);
           }
         }
       }, [api, store, onRefreshError]);
       ```
     - Graceful Failure Recovery: If `refresh()` encounters an exception, logs structured diagnostics via `console.error('[useBootstrapLibrary] Refresh failed:', { error: sanitizeUserPaths(err instanceof Error ? err.message : String(err)), stack: err instanceof Error && err.stack ? sanitizeUserPaths(err.stack) : undefined })`, invokes `onRefreshError?.(errorObj)` where `const errorObj = err instanceof Error ? err : new Error(String(err))`, resets `isRefreshing: false` in a `finally` block, and preserves the existing loaded library in store without transitioning top-level app state to fatal `status: 'error'`.

     ```typescript
     import type { UiStorageAdapter } from '../state/ui-runtime-state';

     export const KNOWN_THEMES = ['system', 'light', 'dark'] as const;
     export type UiTheme = (typeof KNOWN_THEMES)[number];

     export function applyTheme(nextTheme?: string, storage?: UiStorageAdapter): string {
       const raw = nextTheme || storage?.getItem('yumeshelf_theme') || 'system';
       const resolvedTheme = KNOWN_THEMES.includes(raw as UiTheme) ? raw : 'system';
       if (typeof document !== 'undefined' && document.body) {
         KNOWN_THEMES.forEach((t) => document.body.classList.remove(`${t}-theme`));
         document.body.classList.add(`${resolvedTheme}-theme`);
       }
       if (nextTheme && storage) {
         storage.setItem('yumeshelf_theme', resolvedTheme);
       }
       return resolvedTheme;
     }
     ```
   - Invoked synchronously (`applyTheme(undefined, storage)`) during bootstrap in `useBootstrapLibrary` and `App.tsx` on initial mount to prevent dark/light theme flashing.
