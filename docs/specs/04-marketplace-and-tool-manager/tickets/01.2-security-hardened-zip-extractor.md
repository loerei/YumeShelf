# 01.2 — Security-Hardened Zip Decompression Engine

## Epic
PRD 04: Community Add-on Marketplace, Task Runner & Cascading Tool Manager

## What to build
Harden and refactor the existing `src/main/core/zip-extractor.ts` module in-place into a non-blocking, security-hardened archive extraction engine with Zip Slip path traversal mitigation, symlink escape neutralization, atomic staging extraction (`.staging_<tool-id>_<timestamp>/`), and Zip Bomb resource limits.

## Blocked by
- None (Standalone Security Primitive)

## Status
ready-for-agent

## Acceptance criteria
- [ ] Refactor `src/main/core/zip-extractor.ts` in-place to use asynchronous, non-blocking libuv stream decompression (`zlib.inflateRaw`) to prevent Node.js event loop stutter during large archive unpacking.
- [ ] Enforce Zip Slip protection: sanitize every destination path, resolve against base target directory via `path.resolve`, and verify `resolvedPath === targetDir || resolvedPath.startsWith(targetDir + path.sep)`. Reject archive entries attempting path traversal outside destination root.
- [ ] Reject archive entries containing Windows DOS reserved device names matching `/^(CON|PRN|AUX|NUL|COM[1-9]|LPT[1-9])(\..*)?$/i` on Windows destinations or NTFS Alternate Data Stream colons (`:` / `::$DATA`).
- [ ] Neutralize symlink escapes: reject or ignore symbolic link and hardlink entry creation during archive unpacking to eliminate symlink traversal attacks.
- [ ] Implement Zip Bomb safety caps: reject archives exceeding 2GB total uncompressed size, 500MB single entry uncompressed size, or 10,000 file entries.
- [ ] Implement atomic staging extraction: unpack archives into a temporary sibling staging folder (`userData/addons/.staging_<tool-id>_<timestamp>/`) and perform an atomic directory rename (`fs.promises.rename`) to final destination upon successful verification. Roll back and delete staging directory on any error.
- [ ] Unit tests for Zip Slip path traversal rejection, Zip Bomb size limit abortion, corrupted archive handling, atomic staging extraction, and failure rollback using synthetic zip fixtures.
- [ ] Execute automated unit tests via `npm run test:node -- tests/zip-extractor.test.js`.
