# 02.1 — Headless Library Section Projections & Library Stacks Custom Order ($B$)

## Epic
PRD: Sort By Folder (Variant C) & Game Card Drag-Drop Migration to SortableJS

## What to build
Implement pure, headless domain module `src/renderer/library/library-sections.ts` for projecting library view sections across all view modes and tabs:
1. `mapGameToRootFolder(game: any, rootPathsOrCanonicalRoots: string[], targetPlatform?: PlatformInput)`: accepts pre-computed canonical roots (`canonicalRoots: string[]`) or resolves canonical roots via `subsumeLibraryPaths(rootPaths, targetPlatform)` before evaluating path containment via `isSubsumedBy(gamePath, root, targetPlatform)` (leveraging `src/shared/path-subsumption.ts`), eliminating redundant $O(N \times R^2)$ path subsumption during card rendering loops. When checking path prefix containment against canonical roots, guard against duplicate trailing separators on drive roots (`const rootWithSep = normRoot.endsWith(sep) ? normRoot : (normRoot + sep);`), ensuring drive roots like `C:/` or `D:/` match direct children without double-separator distortion (`C://`). Defensively checks for mascot cards or missing folder paths (`const targetGame = game?.primaryGame || game; if (!targetGame || targetGame.isMascotCard || !targetGame.folderPath) return null;`), supporting both multi-instance stack items (where folder path resides on `primaryGame.folderPath`) and raw game entries, preventing stack items from evaluating to `null` and projecting empty folder sections.
2. `projectLibrarySections(params)`: computes canonical roots via `const canonicalRoots = subsumeLibraryPaths(params.rootPaths, params.targetPlatform)` and iterates over `canonicalRoots` (not raw `params.rootPaths`) when generating `folderSections` for the `'all'` shelf tab, projecting sections across all view and tab states:
   - Non-folder sorts (`date`, `played`, `az`, `custom`): `{ favoritesSection, allGamesSection }`.
    - Folder sort (`folder`):
      - Tab `all`: `{ favoritesSection, folderSections }` where each folder section has `path`, `displayName` (resolved safely via own-property check passing `params.targetPlatform`: `const normalizedKey = normalizePathForPlatform(path, params.targetPlatform); (folderAliases && Object.prototype.hasOwnProperty.call(folderAliases, normalizedKey) && folderAliases[normalizedKey]?.trim()) ? folderAliases[normalizedKey].trim() : getFolderBaseName(path)`), `games`, `isEmpty`, `isCollapsible: true`. Favorited games appear in both favorites and folder sections (dual placement). Subsumed child paths are aggregated under their ancestor root rather than generating duplicate or empty sections.
       - Tab `fav`: `{ favoritesSection }`
        - Tab `<folder-id>`: single folder section with `isCollapsible: false`. If `activeTabId` is neither `'all'` nor `'fav'` and does not match any valid folder path in `canonicalRoots` (evaluated via platform-normalized comparison `canonicalRoots.some(r => normalizePathForPlatform(r, params.targetPlatform) === normalizePathForPlatform(params.activeTabId, params.targetPlatform))`, e.g. when an active library folder path is removed in Settings or subsumed by a newly added parent directory), safely fall back to projecting the `'all'` tab view (`{ favoritesSection, folderSections }`).
      - Defensively handles mascot cards (`isMascotCard: true`), keeping them visible in flat sorts without throwing unhandled path errors.

Update `src/renderer/library-stacks.ts`:
- In `buildLibraryViewItems`, when `type === 'custom' || type === 'folder'`, normalize and supply `customOrder`. Pre-index `customOrder` into an $O(1)$ key-to-index lookup `Map<string, number>` prior to `Array.prototype.sort`, and use $O(1)$ map lookups inside `compareGames` symmetrically for both `type === 'custom'` and `type === 'folder'` rather than linear $O(N)$ `order.indexOf` scans, bounding sorting complexity strictly to $O(N \log N)$ and preventing main-thread event loop freezes on large libraries.
- In `compareGames`, when sorting by `type === 'custom' || type === 'folder'`, sort games using $O(1)$ map lookups against pre-indexed `customOrder` so that card reordering within folder containers persists and projects deterministically instead of reverting to alphabetical order on re-render. Guarantee that unmapped game keys resolve to a deterministic boundary index (`orderMap.get(key) ?? Number.MAX_SAFE_INTEGER`), ensuring comparator arithmetic never produces `NaN` and sorting maintains strict weak ordering.
- Update `getGroupedKeysForGame(targetGame: GameEntry): string[]` to inspect `targetGame.instances` when present, returning an array containing `getGameKey(targetGame)` and all sibling instance keys (`instance.gameKey`), deduplicated.

Provide comprehensive Vitest unit tests in `src/renderer/library/library-sections.test.ts` and `src/renderer/library-stacks.test.ts`.
